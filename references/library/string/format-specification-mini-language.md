# string — Format specification mini-language

>
| Type | Meaning |
| --- | --- |
| `'e'` | Scientific notation. At a chosen precision `p`, renders the number in scientific notation, the letter 'e' standing between the coefficient and the exponent. One digit sits before the decimal point and `p` digits after it, making `p + 1` significant digits in all. When no precision is stated, it applies `6` digits past the decimal point for `float` and prints every coefficient digit for `Decimal`. Should `p=0`, the decimal point disappears unless the `#` option comes into play. For `float`, the exponent never has fewer than two digits, and it reads zero when the value is zero. |
| `'E'` | Scientific notation. Behaves like `'e'`, only with an upper case 'E' serving as the separator character. |
| `'f'` | Fixed-point notation. At a chosen precision `p`, renders the number as a decimal number bearing precisely `p` digits past the decimal point. When no precision is stated, it applies `6` digits after the decimal point for `float` and a precision generous enough to print every coefficient digit for `Decimal`. Should `p=0`, the decimal point is dropped unless the `#` option is invoked. |
| `'F'` | Fixed-point notation. Identical to `'f'`, save that it turns `nan` into `NAN` and `inf` into `INF`. |
| `'g'` | General format. At a chosen precision `p >= 1`, this rounds the number to `p` significant digits and then lays out the result in fixed-point format or in scientific notation, whichever its magnitude calls for. A precision of `0` is read as standing in for a precision of `1`. The exact rules run thus: imagine the result, formatted under presentation type `'e'` with precision `p-1`, would carry exponent `exp`. Then, where `m <= exp < p` (with `m` being -4 for floats and -6 for `Decimals`), the number takes presentation type `'f'` and precision `p-1-exp`. In every other case it takes presentation type `'e'` and precision `p-1`. Either way, meaningless trailing zeros are stripped from the significand, and the decimal point too is stripped when no digits remain after it, barring use of the `'#'` option. When no precision is stated, it applies `6` significant digits for `float`. For `Decimal`, the result's coefficient is built out of the value's coefficient digits; scientific notation kicks in for values below `1e-6` in absolute value and for values whose least significant digit has a place value above 1, with fixed-point notation taking over otherwise. Positive and negative infinity, positive and negative zero, and nans come out as `inf`, `-inf`, `0`, `-0` and `nan` in turn, no matter the precision. |
| `'G'` | General format. Mirrors `'g'`, except it flips to `'E'` once the number grows too large. The renderings of infinity and NaN come out uppercased as well. |
| `'n'` | Number. Equivalent to `'g'`, but it draws on the current locale setting to drop in the right digit group separators for a number's integral part. Bear in mind that the default locale isn't the system locale. According to your situation, you might want to set `LC_NUMERIC` via `locale.setlocale()` ahead of using `'n'`. |
| `'%'` | Percentage. Scales the number by 100 and shows it in fixed (`'f'`) format, with a percent sign appended. |
| None | With `float`, this resembles the `'g'` type, except that whenever fixed-point notation renders the result, it always keeps at least one digit beyond the decimal point and flips over to scientific notation once `exp >= p - 1`. Where the precision goes unstated, that precision grows as large as it must to portray the supplied value faithfully. With `Decimal`, this matches either `'g'` or `'G'` according to what `context.capitals` holds for the current decimal context. The net result is to reproduce the output of `str()` as reshaped by the other format modifiers. |

The outcome ought to be rounded properly to a stated precision `p` of digits past the decimal point. For [`float`](https://docs.python.org/3.14/library/functions.html#float), the rounding mode follows that of the [`round()`](https://docs.python.org/3.14/library/functions.html#round) builtin, whereas for [`Decimal`](https://docs.python.org/3.14/library/decimal.html#decimal.Decimal) the rounding mode belonging to the current [context](https://docs.python.org/3.14/library/decimal.html#decimal-context) applies.

For [`complex`](https://docs.python.org/3.14/library/functions.html#complex), the presentation types on offer coincide with those for [`float`](https://docs.python.org/3.14/library/functions.html#float) (with `'%'` ruled out). A complex number's real and imaginary parts alike are rendered as floating-point numbers per the chosen presentation type. Between them stands the obligatory sign of the imaginary part, which itself closes with a `j` suffix. Where the presentation type is left out, the outcome lines up with the output of [`str()`](https://docs.python.org/3.14/library/stdtypes.html#str) — complex numbers whose real part is non-zero get wrapped in parentheses as well — perhaps reshaped by other format modifiers.
