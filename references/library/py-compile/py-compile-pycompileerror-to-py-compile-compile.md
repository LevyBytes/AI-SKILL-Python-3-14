### `py_compile` — Compile Python source files

**Source code:** [Lib/py_compile.py](https://github.com/python/cpython/tree/3.14/Lib/py_compile.py)

---

The `py_compile` module hands you one function to produce a byte-code file from a source file, plus another that runs when the module source file is launched as a script.

While rarely required, this function earns its keep when installing modules for shared use, particularly where some users may lack permission to write the byte-code cache files in the directory holding the source code.

 *exception *py_compile.PyCompileError

Exception raised whenever an error crops up during the attempt to compile the file.

 py_compile.compile(*file*, *cfile=None*, *dfile=None*, *doraise=False*, *optimize=-1*, *invalidation_mode=PycInvalidationMode.TIMESTAMP*, *quiet=0*)

Compile a source file into byte-code and emit the byte-code cache file. That source code gets loaded out of the file named *file*. The byte-code lands in *cfile*, which defaults to the [**PEP 3147**](https://peps.python.org/pep-3147/)/[**PEP 488**](https://peps.python.org/pep-0488/) path, closing in `.pyc`. To illustrate, if *file* is `/foo/bar/baz.py` then *cfile* will default to `/foo/bar/__pycache__/baz.cpython-32.pyc` for Python 3.2. Should *dfile* be supplied, it stands in for *file* as the name of the source file from which source lines get pulled for display in exception tracebacks. Should *doraise* be true, a `PyCompileError` gets raised once an error turns up while compiling *file*. Should *doraise* be false (the default), an error string lands in `sys.stderr`, yet no exception gets raised. This function hands back the path to the byte-compiled file, i.e. whatever *cfile* value was used.

The *doraise* and *quiet* arguments govern how errors get handled while compiling file. Should *quiet* be 0 or 1, with *doraise* false, the default behaviour kicks in: an error string lands in `sys.stderr`, and the function hands back `None` rather than a path. Should *doraise* be true, a `PyCompileError` gets raised instead. Should *quiet* be 2, though, no message lands anywhere, and *doraise* carries no effect.

Should the path that *cfile* resolves to (whether spelled out explicitly or computed) be a symlink or non-regular file, [`FileExistsError`](https://docs.python.org/3.14/library/exceptions.html#FileExistsError) gets raised. This serves as a warning that import will convert those paths into regular files if it's permitted to write byte-compiled files to them. It's a side-effect of import leaning on file renaming to drop the final byte-compiled file into place so as to head off concurrent file writing issues.

*optimize* governs the optimization level and gets handed to the built-in `compile()` function. The default of `-1` picks the optimization level of the current interpreter.

*invalidation_mode* should be a member of the `PycInvalidationMode` enum and governs how the generated bytecode cache gets invalidated at runtime. The default is `PycInvalidationMode.CHECKED_HASH` should the `SOURCE_DATE_EPOCH` environment variable be set, otherwise the default is `PycInvalidationMode.TIMESTAMP`.

Changed in version 3.2: The default value of *cfile* was switched to be [**PEP 3147**](https://peps.python.org/pep-3147/)-compliant. Formerly the default ran *file* + `'c'` (`'o'` where optimization had been turned on). The *optimize* parameter joined here as well.

Changed in version 3.4: The code was switched over to [`importlib`](https://docs.python.org/3.14/library/importlib.html#module-importlib) for writing the byte-code cache file. This makes file creation/writing semantics line up with `importlib`'s, e.g. permissions, write-and-move semantics, etc. The caveat that [`FileExistsError`](https://docs.python.org/3.14/library/exceptions.html#FileExistsError) gets raised should *cfile* be a symlink or non-regular file joined here too.

Changed in version 3.7: The *invalidation_mode* parameter joined here, per the spec in [**PEP 552**](https://peps.python.org/pep-0552/). Should the `SOURCE_DATE_EPOCH` environment variable be set, *invalidation_mode* gets forced over to `PycInvalidationMode.CHECKED_HASH`.

Changed in version 3.7.2: The `SOURCE_DATE_EPOCH` environment variable stops overriding the *invalidation_mode* argument's value, instead settling its default value.

Changed in version 3.8: The *quiet* parameter joined here.
