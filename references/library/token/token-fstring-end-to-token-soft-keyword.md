# token: `token.FSTRING_END`, `token.TSTRING_START`, `token.TSTRING_MIDDLE`, `token.TSTRING_END`, `token.ENDMARKER`, `token.ENCODING`, `token.TYPE_IGNORE`, `token.TYPE_COMMENT`, `token.SOFT_KEYWORD`

token.FSTRING_END

Token value used to indicate the end of a [f-string](https://docs.python.org/3.14/reference/lexical_analysis.html#f-strings).

**CPython implementation detail:** The token string contains the closing quote(s).

 token.TSTRING_START

Token value used to indicate the beginning of a template string literal.

**CPython implementation detail:** The token string carries the prefix and the opening quote(s), yet none of the literal's contents.

Added in version 3.14.

 token.TSTRING_MIDDLE

A token value covering literal text within a template string literal, format specifications included.

**CPython implementation detail:** The replacement fields (in other words, the non-literal parts of t-strings) draw on the same tokens as other expressions and are bounded by `LBRACE`, `RBRACE`, `EXCLAMATION` and `COLON` tokens.

Added in version 3.14.

 token.TSTRING_END

Token value used to indicate the end of a template string literal.

**CPython implementation detail:** The token string contains the closing quote(s).

Added in version 3.14.

 token.ENDMARKER

Token value that indicates the end of input. Used in [top-level grammar rules](https://docs.python.org/3.14/reference/toplevel_components.html#top-level).

 token.ENCODING

A token value flagging the encoding applied to decode the source bytes into text. The very first token that [`tokenize.tokenize()`](https://docs.python.org/3.14/library/tokenize.html#tokenize.tokenize) yields will invariably be an `ENCODING` token.

**CPython implementation detail:** The C tokenizer makes no use of this token type, but the [`tokenize`](https://docs.python.org/3.14/library/tokenize.html#module-tokenize) module requires it.

The token types below are not generated by the [`tokenize`](https://docs.python.org/3.14/library/tokenize.html#module-tokenize) module; they exist for special uses inside the tokenizer or parser:

 token.TYPE_IGNORE

A token value signalling that a `type: ignore` comment was spotted. Such tokens get produced in place of ordinary `COMMENT` tokens only when the [`PyCF_TYPE_COMMENTS`](https://docs.python.org/3.14/library/ast.html#ast.PyCF_TYPE_COMMENTS) flag is in effect.

 token.TYPE_COMMENT

A token value signalling that a type comment was spotted. Such tokens get produced in place of ordinary `COMMENT` tokens only when the [`PyCF_TYPE_COMMENTS`](https://docs.python.org/3.14/library/ast.html#ast.PyCF_TYPE_COMMENTS) flag is in effect.

 token.SOFT_KEYWORD

Token value indicating a [soft keyword](https://docs.python.org/3.14/reference/lexical_analysis.html#soft-keywords).

This value is never produced by the tokenizer. To test for a soft keyword, hand a `NAME` token's string to [`keyword.issoftkeyword()`](https://docs.python.org/3.14/library/keyword.html#keyword.issoftkeyword).
