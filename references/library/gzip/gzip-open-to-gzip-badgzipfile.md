# Gzip

### `gzip` - Support for **gzip** files

**Source code:** [Lib/gzip.py](https://github.com/python/cpython/tree/3.14/Lib/gzip.py)

---

This module offers a straightforward way to compress and decompress files, behaving much as the GNU utilities **gzip** and **gunzip** do.

It counts as an [optional module](https://docs.python.org/3.14/glossary.html#term-optional-module). Should your CPython build lack it, turn to documentation from your distributor (whoever it was that handed Python to you). If you happen to be the distributor, consult [Requirements for optional modules](https://docs.python.org/3.14/using/configure.html#optional-module-requirements).

Compression of the data is handled by the [`zlib`](https://docs.python.org/3.14/library/zlib.html#module-zlib) module.

The `gzip` module furnishes the `GzipFile` class together with the `open()`, `compress()`, and `decompress()` convenience functions. The `GzipFile` class both reads and writes **gzip**-format files, transparently compressing or decompressing the data so it presents itself like an ordinary [file object](https://docs.python.org/3.14/glossary.html#term-file-object).

Be aware that other file formats decompressible by the **gzip** and **gunzip** utilities, for instance those generated by **compress** and **pack**, are outside this module's support.

The module defines the items below:

 gzip.open(*filename*, *mode='rb'*, *compresslevel=9*, *encoding=None*, *errors=None*, *newline=None*)

Open up a gzip-compressed file in either binary or text mode and return a [file object](https://docs.python.org/3.14/glossary.html#term-file-object).

The *filename* argument may be a genuine filename (a [`str`](https://docs.python.org/3.14/library/stdtypes.html#str) or [`bytes`](https://docs.python.org/3.14/library/stdtypes.html#bytes) object) or an already-open file object to read from or write to.

The *mode* argument may take any of `'r'`, `'rb'`, `'a'`, `'ab'`, `'w'`, `'wb'`, `'x'` or `'xb'` for binary mode, or `'rt'`, `'at'`, `'wt'`, or `'xt'` for text mode. `'rb'` is the default.

The *compresslevel* argument is an integer running from 0 to 9, just as with the `GzipFile` constructor.

In binary mode this function matches the `GzipFile` constructor: `GzipFile(filename, mode, compresslevel)`. Here the *encoding*, *errors* and *newline* arguments have to be omitted.

In text mode a `GzipFile` object is built and then wrapped within an [`io.TextIOWrapper`](https://docs.python.org/3.14/library/io.html#io.TextIOWrapper) instance carrying the given encoding, error-handling behavior, and line ending(s).

Changed in version 3.3: Gained the ability to take *filename* as a file object, to operate in text mode, and to accept the *encoding*, *errors* and *newline* arguments.

Changed in version 3.4: Added support for the `'x'`, `'xb'` and `'xt'` modes.

Changed in version 3.6: Accepts a [path-like object](https://docs.python.org/3.14/glossary.html#term-path-like-object).

 *exception *gzip.BadGzipFile

An exception thrown when a gzip file is invalid. It descends from [`OSError`](https://docs.python.org/3.14/library/exceptions.html#OSError). Invalid gzip files may additionally give rise to [`EOFError`](https://docs.python.org/3.14/library/exceptions.html#EOFError) and [`zlib.error`](https://docs.python.org/3.14/library/zlib.html#zlib.error).

Added in version 3.8.
