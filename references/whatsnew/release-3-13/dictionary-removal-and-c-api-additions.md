# What's New In Python 3.13 / C API Changes / New Features - tracemalloc

Introduce the [`PyDict_Pop()`](https://docs.python.org/3.14/c-api/dict.html#c.PyDict_Pop) and [`PyDict_PopString()`](https://docs.python.org/3.14/c-api/dict.html#c.PyDict_PopString) functions, which drop a key from a dictionary and may hand back the value that was dropped. The behavior parallels [`dict.pop()`](https://docs.python.org/3.14/library/stdtypes.html#dict.pop), except that no fallback value exists and [`KeyError`](https://docs.python.org/3.14/library/exceptions.html#KeyError) stays silent when a key is absent. (Contributed by Stefan Behnel and Victor Stinner in [gh-111262](https://github.com/python/cpython/issues/111262).)

- Introduce the [`PyMapping_GetOptionalItem()`](https://docs.python.org/3.14/c-api/mapping.html#c.PyMapping_GetOptionalItem) and [`PyMapping_GetOptionalItemString()`](https://docs.python.org/3.14/c-api/mapping.html#c.PyMapping_GetOptionalItemString) functions, which serve as alternatives to [`PyObject_GetItem()`](https://docs.python.org/3.14/c-api/object.html#c.PyObject_GetItem) and [`PyMapping_GetItemString()`](https://docs.python.org/3.14/c-api/mapping.html#c.PyMapping_GetItemString) respectively. Should the sought key be absent from the mapping, the additions skip raising [`KeyError`](https://docs.python.org/3.14/library/exceptions.html#KeyError). When an absent key ought not count as a failure, these forms run faster and read more cleanly. (Contributed by Serhiy Storchaka in [gh-106307](https://github.com/python/cpython/issues/106307).)

- Introduce the [`PyObject_GetOptionalAttr()`](https://docs.python.org/3.14/c-api/object.html#c.PyObject_GetOptionalAttr) and [`PyObject_GetOptionalAttrString()`](https://docs.python.org/3.14/c-api/object.html#c.PyObject_GetOptionalAttrString) functions, which serve as alternatives to [`PyObject_GetAttr()`](https://docs.python.org/3.14/c-api/object.html#c.PyObject_GetAttr) and [`PyObject_GetAttrString()`](https://docs.python.org/3.14/c-api/object.html#c.PyObject_GetAttrString) respectively. Should the sought attribute be missing on the object, the additions skip raising [`AttributeError`](https://docs.python.org/3.14/library/exceptions.html#AttributeError). When an absent attribute ought not count as a failure, these forms run faster and read more cleanly. (Contributed by Serhiy Storchaka in [gh-106521](https://github.com/python/cpython/issues/106521).)

- Introduce the [`PyErr_FormatUnraisable()`](https://docs.python.org/3.14/c-api/exceptions.html#c.PyErr_FormatUnraisable) function, an extension over [`PyErr_WriteUnraisable()`](https://docs.python.org/3.14/c-api/exceptions.html#c.PyErr_WriteUnraisable) that lets you tailor the warning text. (Contributed by Serhiy Storchaka in [gh-108082](https://github.com/python/cpython/issues/108082).)

- Introduce new functions that hand back a [strong reference](https://docs.python.org/3.14/glossary.html#term-strong-reference) rather than a [borrowed reference](https://docs.python.org/3.14/glossary.html#term-borrowed-reference) for a frame's locals, globals, and builtins, in line with PEP 667:

  - [`PyEval_GetFrameBuiltins()`](https://docs.python.org/3.14/c-api/reflection.html#c.PyEval_GetFrameBuiltins) replaces [`PyEval_GetBuiltins()`](https://docs.python.org/3.14/c-api/reflection.html#c.PyEval_GetBuiltins)

  - [`PyEval_GetFrameGlobals()`](https://docs.python.org/3.14/c-api/reflection.html#c.PyEval_GetFrameGlobals) replaces [`PyEval_GetGlobals()`](https://docs.python.org/3.14/c-api/reflection.html#c.PyEval_GetGlobals)

  - [`PyEval_GetFrameLocals()`](https://docs.python.org/3.14/c-api/reflection.html#c.PyEval_GetFrameLocals) replaces [`PyEval_GetLocals()`](https://docs.python.org/3.14/c-api/reflection.html#c.PyEval_GetLocals)

(Contributed by Mark Shannon and Tian Gao in [gh-74929](https://github.com/python/cpython/issues/74929).)

- Introduce the [`Py_GetConstant()`](https://docs.python.org/3.14/c-api/object.html#c.Py_GetConstant) and [`Py_GetConstantBorrowed()`](https://docs.python.org/3.14/c-api/object.html#c.Py_GetConstantBorrowed) functions that fetch [strong](https://docs.python.org/3.14/glossary.html#term-strong-reference) or [borrowed](https://docs.python.org/3.14/glossary.html#term-borrowed-reference) references to constants. As an illustration, `Py_GetConstant(Py_CONSTANT_ZERO)` yields a strong reference to the zero constant. (Contributed by Victor Stinner in [gh-115754](https://github.com/python/cpython/issues/115754).)

- Introduce the [`PyImport_AddModuleRef()`](https://docs.python.org/3.14/c-api/import.html#c.PyImport_AddModuleRef) function to stand in for [`PyImport_AddModule()`](https://docs.python.org/3.14/c-api/import.html#c.PyImport_AddModule), handing back a [strong reference](https://docs.python.org/3.14/glossary.html#term-strong-reference) rather than a [borrowed reference](https://docs.python.org/3.14/glossary.html#term-borrowed-reference). (Contributed by Victor Stinner in [gh-105922](https://github.com/python/cpython/issues/105922).)

- Introduce the [`Py_IsFinalizing()`](https://docs.python.org/3.14/c-api/interp-lifecycle.html#c.Py_IsFinalizing) function that reports whether the principal Python interpreter is [shutting down](https://docs.python.org/3.14/glossary.html#term-interpreter-shutdown). (Contributed by Victor Stinner in [gh-108014](https://github.com/python/cpython/issues/108014).)

- Introduce the [`PyList_GetItemRef()`](https://docs.python.org/3.14/c-api/list.html#c.PyList_GetItemRef) function to stand in for [`PyList_GetItem()`](https://docs.python.org/3.14/c-api/list.html#c.PyList_GetItem), handing back a [strong reference](https://docs.python.org/3.14/glossary.html#term-strong-reference) rather than a [borrowed reference](https://docs.python.org/3.14/glossary.html#term-borrowed-reference). (Contributed by Sam Gross in [gh-114329](https://github.com/python/cpython/issues/114329).)

- Introduce the [`PyList_Extend()`](https://docs.python.org/3.14/c-api/list.html#c.PyList_Extend) and [`PyList_Clear()`](https://docs.python.org/3.14/c-api/list.html#c.PyList_Clear) functions that echo the Python [`list.extend()`](https://docs.python.org/3.14/library/stdtypes.html#list.extend) and [`list.clear()`](https://docs.python.org/3.14/library/stdtypes.html#list.clear) methods. (Contributed by Victor Stinner in [gh-111138](https://github.com/python/cpython/issues/111138).)

- Introduce the [`PyLong_AsInt()`](https://docs.python.org/3.14/c-api/long.html#c.PyLong_AsInt) function. Its behavior tracks that of [`PyLong_AsLong()`](https://docs.python.org/3.14/c-api/long.html#c.PyLong_AsLong), yet it deposits the outcome into a C int in place of a C long. (Contributed by Victor Stinner in [gh-108014](https://github.com/python/cpython/issues/108014).)

- Introduce the [`PyLong_AsNativeBytes()`](https://docs.python.org/3.14/c-api/long.html#c.PyLong_AsNativeBytes), [`PyLong_FromNativeBytes()`](https://docs.python.org/3.14/c-api/long.html#c.PyLong_FromNativeBytes), and [`PyLong_FromUnsignedNativeBytes()`](https://docs.python.org/3.14/c-api/long.html#c.PyLong_FromUnsignedNativeBytes) functions that ease conversion across native integer types and Python [`int`](https://docs.python.org/3.14/library/functions.html#int) objects. (Contributed by Steve Dower in [gh-111140](https://github.com/python/cpython/issues/111140).)

- Introduce the [`PyModule_Add()`](https://docs.python.org/3.14/c-api/module.html#c.PyModule_Add) function, akin to [`PyModule_AddObjectRef()`](https://docs.python.org/3.14/c-api/module.html#c.PyModule_AddObjectRef) and [`PyModule_AddObject()`](https://docs.python.org/3.14/c-api/module.html#c.PyModule_AddObject), yet it consistently steals a reference to the supplied value. (Contributed by Serhiy Storchaka in [gh-86493](https://github.com/python/cpython/issues/86493).)

- Introduce the [`PyObject_GenericHash()`](https://docs.python.org/3.14/c-api/hash.html#c.PyObject_GenericHash) function that carries out the standard hashing routine for a Python object. (Contributed by Serhiy Storchaka in [gh-113024](https://github.com/python/cpython/issues/113024).)

- Introduce the [`Py_HashPointer()`](https://docs.python.org/3.14/c-api/hash.html#c.Py_HashPointer) function that derives a hash from a raw pointer. (Contributed by Victor Stinner in [gh-111545](https://github.com/python/cpython/issues/111545).)

- Introduce the [`PyObject_VisitManagedDict()`](https://docs.python.org/3.14/c-api/object.html#c.PyObject_VisitManagedDict) and [`PyObject_ClearManagedDict()`](https://docs.python.org/3.14/c-api/object.html#c.PyObject_ClearManagedDict) functions, which the traverse and clear routines of a type bearing the [`Py_TPFLAGS_MANAGED_DICT`](https://docs.python.org/3.14/c-api/typeobj.html#c.Py_TPFLAGS_MANAGED_DICT) flag are required to invoke. To employ these functions under Python 3.11 and 3.12, reach for the [pythoncapi-compat project](https://github.com/python/pythoncapi-compat/). (Contributed by Victor Stinner in [gh-107073](https://github.com/python/cpython/issues/107073).)

- Introduce the [`PyRefTracer_SetTracer()`](https://docs.python.org/3.14/c-api/profiling.html#c.PyRefTracer_SetTracer) and [`PyRefTracer_GetTracer()`](https://docs.python.org/3.14/c-api/profiling.html#c.PyRefTracer_GetTracer) functions, which let you observe object creation and destruction much as the [`tracemalloc`](https://docs.python.org/3.14/library/tracemalloc.html#module-tracemalloc) module already does. (Contributed by Pablo Galindo in [gh-93502](https://github.com/python/cpython/issues/93502).)
