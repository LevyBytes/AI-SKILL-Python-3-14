# What’s New in Python 2.6 / PEP 370: Per-user `site-packages` Directory

### PEP 370: Per-user `site-packages` Directory

Whenever you launch Python, the `sys.path` module search path normally contains a directory whose path finishes with `"site-packages"`. The purpose of that directory is to keep locally installed packages reachable for everyone who uses the machine or a given site installation.

Python 2.6 brings in a convention for per-user site directories. Which directory that is depends on the platform:

- Unix and Mac OS X: `~/.local/`

- Windows: `%APPDATA%/Python`

Inside that directory you’ll find version-specific subdirectories, for instance `lib/python2.6/site-packages` on Unix/Mac OS and `Python26/site-packages` on Windows.

Should the default directory not suit you, an environment variable can override it. [`PYTHONUSERBASE`](https://docs.python.org/3.14/using/cmdline.html#envvar-PYTHONUSERBASE) sets the root directory used for all Python versions supporting this feature. Under Windows, you can point the directory for application-specific data elsewhere by setting the `APPDATA` environment variable. Editing the `site.py` file of your Python installation is another option.

You can turn the feature off completely either by launching Python with the [`-s`](https://docs.python.org/3.14/using/cmdline.html#cmdoption-s) option or by defining the [`PYTHONNOUSERSITE`](https://docs.python.org/3.14/using/cmdline.html#envvar-PYTHONNOUSERSITE) environment variable.
