# What’s New In Python 3.5 / Changes in the Python API — datetime, html.parser, ssl

### Changes in the Python API

- [**PEP 475**](https://peps.python.org/pep-0475/): A system call interrupted by a signal is now retried instead of raising [`InterruptedError`](https://docs.python.org/3.14/library/exceptions.html#InterruptedError), provided the Python signal handler raises no exception.

- Prior to Python 3.5, a [`datetime.time`](https://docs.python.org/3.14/library/datetime.html#datetime.time) object counted as false whenever it stood for midnight in UTC. That behavior was judged obscure and error-prone, so Python 3.5 removed it. Refer to [bpo-13936](https://bugs.python.org/issue?@action=redirect&bpo=13936) for the complete account.

- On a non-blocking socket where the operation would block, the `ssl.SSLSocket.send()` method now raises either [`ssl.SSLWantReadError`](https://docs.python.org/3.14/library/ssl.html#ssl.SSLWantReadError) or [`ssl.SSLWantWriteError`](https://docs.python.org/3.14/library/ssl.html#ssl.SSLWantWriteError). Formerly it returned `0`. (Contributed by Nikolaus Rath in [bpo-20951](https://bugs.python.org/issue?@action=redirect&bpo=20951).)

- A generator's `__name__` attribute now derives from the function name rather than the code name. To get back the code name, use `gen.gi_code.co_name`. Generators additionally gained a `__qualname__` attribute — the qualified name — which now feeds a generator's representation (`repr(gen)`). (Contributed by Victor Stinner in [bpo-21205](https://bugs.python.org/issue?@action=redirect&bpo=21205).)

- Gone now are the deprecated "strict" mode and argument of [`HTMLParser`](https://docs.python.org/3.14/library/html.parser.html#html.parser.HTMLParser), along with `HTMLParser.error()` and the `HTMLParserError` exception. (Contributed by Ezio Melotti in [bpo-15114](https://bugs.python.org/issue?@action=redirect&bpo=15114).) For `HTMLParser`, the *convert_charrefs* argument now defaults to `True`. (Contributed by Berker Peksag in [bpo-21047](https://bugs.python.org/issue?@action=redirect&bpo=21047).)

- While it isn't officially part of the API, it bears mentioning for porting work (such as repairing tests) that error messages once shaped like "'sometype' does not support the buffer protocol" now read "a [bytes-like object](https://docs.python.org/3.14/glossary.html#term-bytes-like-object) is required, not 'sometype'". (Contributed by Ezio Melotti in [bpo-16518](https://bugs.python.org/issue?@action=redirect&bpo=16518).)

-

Should the working directory point at a directory that has since vanished, [`FileNotFoundError`](https://docs.python.org/3.14/library/exceptions.html#FileNotFoundError) is no longer thrown; in its place [`find_spec()`](https://docs.python.org/3.14/library/importlib.html#importlib.machinery.FileFinder.find_spec) hands back `None` **without** storing `None` inside [`sys.path_importer_cache`](https://docs.python.org/3.14/library/sys.html#sys.path_importer_cache), unlike the usual situation ([bpo-22834](https://bugs.python.org/issue?@action=redirect&bpo=22834)).

- The HTTP status codes and their messages, drawn from [`http.client`](https://docs.python.org/3.14/library/http.client.html#module-http.client) and [`http.server`](https://docs.python.org/3.14/library/http.server.html#module-http.server), were consolidated into a shared [`HTTPStatus`](https://docs.python.org/3.14/library/http.html#http.HTTPStatus) enum. To keep older code working, the values still live in `http.client` and `http.server`. (Contributed by Demian Brecht in [bpo-21793](https://bugs.python.org/issue?@action=redirect&bpo=21793).)

- Any import loader that supplies [`exec_module()`](https://docs.python.org/3.14/library/importlib.html#importlib.abc.Loader.exec_module) is now likewise required to supply [`create_module()`](https://docs.python.org/3.14/library/importlib.html#importlib.abc.Loader.create_module) (which triggers a [`DeprecationWarning`](https://docs.python.org/3.14/library/exceptions.html#DeprecationWarning) for now and becomes an outright error in Python 3.6). A loader that derives from [`importlib.abc.Loader`](https://docs.python.org/3.14/library/importlib.html#importlib.abc.Loader) needs no further work; otherwise, just have `create_module()` return `None`. (Contributed by Brett Cannon in [bpo-23014](https://bugs.python.org/issue?@action=redirect&bpo=23014).)

- Historically the [`re.split()`](https://docs.python.org/3.14/library/re.html#re.split) function skipped empty pattern matches, which made the `"x*"` pattern behave just like `"x+"` while the `"\b"` pattern never did anything. From now on, `re.split()` issues a warning whenever the pattern might match an empty string. For safety, stick to patterns that can never match an empty string (for example `"x+"` rather than `"x*"`). A pattern able to match only an empty string (`"\b"` being one) now triggers an error. (Contributed by Serhiy Storchaka in [bpo-22818](https://bugs.python.org/issue?@action=redirect&bpo=22818).)

- The dict-like interface of [`http.cookies.Morsel`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel) was brought into line with itself: comparing morsels now weighs both the [`key`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel.key) and the [`value`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel.value), [`copy()`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel.copy) yields a `Morsel` instance in place of a [`dict`](https://docs.python.org/3.14/library/stdtypes.html#dict), and [`update()`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel.update) now throws an exception should any key in the supplied dictionary be invalid. On top of that, the undocumented *LegalChars* parameter belonging to [`set()`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel.set) is deprecated and now disregarded. (Contributed by Demian Brecht in [bpo-2211](https://bugs.python.org/issue?@action=redirect&bpo=2211).)

- [**PEP 488**](https://peps.python.org/pep-0488/) did away with `.pyo` files in Python and brought in the optional `opt-` tag within `.pyc` file names. To help manage that `opt-` tag, [`importlib.util.cache_from_source()`](https://docs.python.org/3.14/library/importlib.html#importlib.util.cache_from_source) picked up an *optimization* parameter. Owing to this, the function's *debug_override* parameter is now deprecated. The Python interpreter also stops accepting `.pyo` files as a file argument, so they no longer accomplish anything when shipped by themselves (that is, sourceless code distribution). And since the bytecode magic number was altered in Python 3.5, every old `.pyo` file produced by earlier Python releases is invalid, this PEP notwithstanding.

- On Linux 3.6 and above, the [`socket`](https://docs.python.org/3.14/library/socket.html#module-socket) module now makes the [`CAN_RAW_FD_FRAMES`](https://docs.python.org/3.14/library/socket.html#socket.CAN_RAW_FD_FRAMES) constant available.

- Following [**RFC 5280**](https://datatracker.ietf.org/doc/html/rfc5280.html), the [`ssl.cert_time_to_seconds()`](https://docs.python.org/3.14/library/ssl.html#ssl.cert_time_to_seconds) function now treats the supplied time as UTC rather than local time. The returned value is, moreover, always an [`int`](https://docs.python.org/3.14/library/functions.html#int). (Contributed by Akira Li in [bpo-19940](https://bugs.python.org/issue?@action=redirect&bpo=19940).)

- In the POT-Creation-Date header, the `pygettext.py` Tool now writes timezones using the conventional +NNNN format.

- For debug output, the [`smtplib`](https://docs.python.org/3.14/library/smtplib.html#module-smtplib) module now writes to [`sys.stderr`](https://docs.python.org/3.14/library/sys.html#sys.stderr) rather than the former module-level `stderr` variable. Any (test) program that relied on patching that module-level variable to grab the debug output will have to be revised so it grabs sys.stderr instead.

- When the empty string is being matched and the indexes fall entirely outside the valid range, the [`str.startswith()`](https://docs.python.org/3.14/library/stdtypes.html#str.startswith) and [`str.endswith()`](https://docs.python.org/3.14/library/stdtypes.html#str.endswith) methods no longer give back `True`. (Contributed by Serhiy Storchaka in [bpo-24284](https://bugs.python.org/issue?@action=redirect&bpo=24284).)

- The [`inspect.getdoc()`](https://docs.python.org/3.14/library/inspect.html#inspect.getdoc) function now hands back documentation strings that were inherited from base classes. There is no longer any need to repeat a documentation string when the inherited one will do. Blocking an inherited string requires giving an empty string (or you may write fresh documentation in its place). This shift alters what the [`pydoc`](https://docs.python.org/3.14/library/pydoc.html#module-pydoc) module and the [`help()`](https://docs.python.org/3.14/library/functions.html#help) function produce. (Contributed by Serhiy Storchaka in [bpo-15582](https://bugs.python.org/issue?@action=redirect&bpo=15582).)

- Nested [`functools.partial()`](https://docs.python.org/3.14/library/functools.html#functools.partial) calls now collapse into a single layer. Anyone who counted on the older behavior can these days either attach an attribute to a `functools.partial()` object or derive a subclass from `functools.partial()`. (Contributed by Alexander Belopolsky in [bpo-7830](https://bugs.python.org/issue?@action=redirect&bpo=7830).)
