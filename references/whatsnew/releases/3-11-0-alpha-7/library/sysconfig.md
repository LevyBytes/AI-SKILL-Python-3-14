# Python 3.11.0 alpha 7 / library / sysconfig

[bpo-45413](https://bugs.python.org/issue?@action=redirect&bpo=45413): Two new [sysconfig installation schemes](https://docs.python.org/3.14/library/sysconfig.html#installation-paths), *posix_venv* and *nt_venv*, are defined for the purpose of bootstrapping fresh virtual environments. A *venv* sysconfig install scheme is also added that resolves to whichever of those two applies. These schemes mirror the existing *posix_prefix* and *nt* install schemes exactly. To build new virtual environments, the [`venv`](https://docs.python.org/3.14/library/venv.html#module-venv) module now relies on the *venv* scheme rather than baking in paths that only depend on the platform. Distributors of Python downstream who tweak the *posix_prefix* or *nt* install scheme in some manner that breaks compatibility with the scheme used inside virtual environments should avoid customizing the *venv* schemes. While Python is executing within a virtual environment, both [`sysconfig.get_default_scheme()`](https://docs.python.org/3.14/library/sysconfig.html#sysconfig.get_default_scheme) and [`sysconfig.get_preferred_scheme()`](https://docs.python.org/3.14/library/sysconfig.html#sysconfig.get_preferred_scheme) called with `key="prefix"` will hand back *venv*.
