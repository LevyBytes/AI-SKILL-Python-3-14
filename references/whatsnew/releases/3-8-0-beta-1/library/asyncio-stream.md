# Python 3.8.0 beta 1 / library / asyncio stream

[bpo-36889](https://bugs.python.org/issue?@action=redirect&bpo=36889): Adds an `asyncio.Stream` class fusing the [`asyncio.StreamReader`](https://docs.python.org/3.14/library/asyncio-stream.html#asyncio.StreamReader) and [`asyncio.StreamWriter`](https://docs.python.org/3.14/library/asyncio-stream.html#asyncio.StreamWriter) capabilities. `asyncio.Stream` operates in readonly, writeonly and readwrite modes. The `asyncio.connect()`, `asyncio.connect_unix()`, `asyncio.connect_read_pipe()` and `asyncio.connect_write_pipe()` factories open `asyncio.Stream` connections. There are `asyncio.StreamServer` and `UnixStreamServer` for running servers via the asyncio.Stream API. [`asyncio.create_subprocess_shell()`](https://docs.python.org/3.14/library/asyncio-subprocess.html#asyncio.create_subprocess_shell) and [`asyncio.create_subprocess_exec()`](https://docs.python.org/3.14/library/asyncio-subprocess.html#asyncio.create_subprocess_exec) are reworked to rely on `asyncio.Stream` rather than the deprecated `StreamReader` and `StreamWriter`. The `asyncio.StreamReader` and `asyncio.StreamWriter` names are deprecated. Reaching for private classes, for instance `asyncio.FlowControlMixing` and `asyncio.StreamReaderProtocol`, beyond the asyncio package is deprecated.
