# Python 3.13.0 alpha 2 / c api / dict

[gh-111262](https://github.com/python/cpython/issues/111262): New [`PyDict_Pop()`](https://docs.python.org/3.14/c-api/dict.html#c.PyDict_Pop) and [`PyDict_PopString()`](https://docs.python.org/3.14/c-api/dict.html#c.PyDict_PopString) helpers drop a key out of a mapping and, when wanted, hand back whatever value was discarded. The behaviour mirrors [`dict.pop()`](https://docs.python.org/3.14/library/stdtypes.html#dict.pop), except there is no default argument and a missing key does not trigger [`KeyError`](https://docs.python.org/3.14/library/exceptions.html#KeyError). Stefan Behnel and Victor Stinner wrote the patch.

[gh-106672](https://github.com/python/cpython/issues/106672): The routines [`PyDict_GetItem()`](https://docs.python.org/3.14/c-api/dict.html#c.PyDict_GetItem), [`PyDict_GetItemString()`](https://docs.python.org/3.14/c-api/dict.html#c.PyDict_GetItemString), [`PyMapping_HasKey()`](https://docs.python.org/3.14/c-api/mapping.html#c.PyMapping_HasKey), [`PyMapping_HasKeyString()`](https://docs.python.org/3.14/c-api/mapping.html#c.PyMapping_HasKeyString), [`PyObject_HasAttr()`](https://docs.python.org/3.14/c-api/object.html#c.PyObject_HasAttr), [`PyObject_HasAttrString()`](https://docs.python.org/3.14/c-api/object.html#c.PyObject_HasAttrString), and [`PySys_GetObject()`](https://docs.python.org/3.14/c-api/sys.html#c.PySys_GetObject) all clear whatever errors arose while they ran; each one now surfaces those errors through [`sys.unraisablehook()`](https://docs.python.org/3.14/library/sys.html#sys.unraisablehook).
