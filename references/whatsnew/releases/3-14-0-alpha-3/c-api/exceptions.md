# Python 3.14.0 alpha 3 / c api / exceptions

[gh-127691](https://github.com/python/cpython/issues/127691): Should the exception argument not be a [`UnicodeError`](https://docs.python.org/3.14/library/exceptions.html#UnicodeError) object, the [Unicode Exception Objects](https://docs.python.org/3.14/c-api/exceptions.html#unicodeexceptions) C API now raises [`TypeError`](https://docs.python.org/3.14/library/exceptions.html#TypeError). Bénédikt Tran supplied the patch.

[gh-123378](https://github.com/python/cpython/issues/123378): Guarantee the [`UnicodeEncodeError.end`](https://docs.python.org/3.14/library/exceptions.html#UnicodeError.end) value that [`PyUnicodeEncodeError_GetEnd()`](https://docs.python.org/3.14/c-api/exceptions.html#c.PyUnicodeEncodeError_GetEnd) returns stays within `[min(1, objlen), max(min(1, objlen), objlen)]`, with *objlen* being the length of [`UnicodeEncodeError.object`](https://docs.python.org/3.14/library/exceptions.html#UnicodeError.object). The same reasoning extends to [`UnicodeDecodeError`](https://docs.python.org/3.14/library/exceptions.html#UnicodeDecodeError), [`UnicodeTranslateError`](https://docs.python.org/3.14/library/exceptions.html#UnicodeTranslateError), and their matching C interface. Bénédikt Tran supplied the patch.

[gh-123378](https://github.com/python/cpython/issues/123378): Guarantee the [`UnicodeEncodeError.start`](https://docs.python.org/3.14/library/exceptions.html#UnicodeError.start) value that [`PyUnicodeEncodeError_GetStart()`](https://docs.python.org/3.14/c-api/exceptions.html#c.PyUnicodeEncodeError_GetStart) returns stays within `[0, max(0, objlen - 1)]`, with *objlen* being the length of [`UnicodeEncodeError.object`](https://docs.python.org/3.14/library/exceptions.html#UnicodeError.object). The same reasoning extends to [`UnicodeDecodeError`](https://docs.python.org/3.14/library/exceptions.html#UnicodeDecodeError), [`UnicodeTranslateError`](https://docs.python.org/3.14/library/exceptions.html#UnicodeTranslateError), and their matching C interface. Bénédikt Tran supplied the patch.

[gh-109523](https://github.com/python/cpython/issues/109523): Pulling text out of a non-blocking stream through `read` can now raise [`BlockingIOError`](https://docs.python.org/3.14/library/exceptions.html#BlockingIOError) whenever the call is unable to hand back bytes right away.
