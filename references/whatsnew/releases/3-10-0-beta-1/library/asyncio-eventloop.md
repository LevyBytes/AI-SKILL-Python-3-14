# Python 3.10.0 beta 1 / library / asyncio eventloop

[bpo-39529](https://bugs.python.org/issue?@action=redirect&bpo=39529): Calling [`asyncio.get_event_loop()`](https://docs.python.org/3.14/library/asyncio-eventloop.html#asyncio.get_event_loop) with no event loop running is now deprecated. A deprecation warning is raised by [`asyncio`](https://docs.python.org/3.14/library/asyncio.html#module-asyncio) helpers that quietly build a [`Future`](https://docs.python.org/3.14/library/asyncio-future.html#asyncio.Future) or [`Task`](https://docs.python.org/3.14/library/asyncio-task.html#asyncio.Task) when no loop is running and no explicit *loop* argument is supplied — namely [`ensure_future()`](https://docs.python.org/3.14/library/asyncio-future.html#asyncio.ensure_future), [`wrap_future()`](https://docs.python.org/3.14/library/asyncio-future.html#asyncio.wrap_future), [`gather()`](https://docs.python.org/3.14/library/asyncio-task.html#asyncio.gather), [`shield()`](https://docs.python.org/3.14/library/asyncio-task.html#asyncio.shield), [`as_completed()`](https://docs.python.org/3.14/library/asyncio-task.html#asyncio.as_completed) plus the constructors for `Future`, `Task`, [`StreamReader`](https://docs.python.org/3.14/library/asyncio-stream.html#asyncio.StreamReader), and `StreamReaderProtocol`.
