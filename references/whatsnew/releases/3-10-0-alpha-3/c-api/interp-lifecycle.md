# Python 3.10.0 alpha 3 / c api / interp lifecycle

[bpo-42260](https://bugs.python.org/issue?@action=redirect&bpo=42260): The [`Py_GetPath()`](https://docs.python.org/3.14/c-api/interp-lifecycle.html#c.Py_GetPath), [`Py_GetPrefix()`](https://docs.python.org/3.14/c-api/interp-lifecycle.html#c.Py_GetPrefix), [`Py_GetExecPrefix()`](https://docs.python.org/3.14/c-api/interp-lifecycle.html#c.Py_GetExecPrefix), [`Py_GetProgramFullPath()`](https://docs.python.org/3.14/c-api/interp-lifecycle.html#c.Py_GetProgramFullPath), [`Py_GetPythonHome()`](https://docs.python.org/3.14/c-api/interp-lifecycle.html#c.Py_GetPythonHome) and [`Py_GetProgramName()`](https://docs.python.org/3.14/c-api/interp-lifecycle.html#c.Py_GetProgramName) functions hand back `NULL` whenever invoked ahead of [`Py_Initialize()`](https://docs.python.org/3.14/c-api/interp-lifecycle.html#c.Py_Initialize) (that is, before Python is initialized). Reach for the new [Python Initialization Configuration API](https://docs.python.org/3.14/c-api/init_config.html#init-config) to fetch the [Python Path Configuration.](https://docs.python.org/3.14/c-api/init_config.html#init-path-config). Victor Stinner wrote the patch.

[bpo-42260](https://bugs.python.org/issue?@action=redirect&bpo=42260): Invoking [`Py_Initialize()`](https://docs.python.org/3.14/c-api/interp-lifecycle.html#c.Py_Initialize) a second time now refreshes a wider set of [`sys`](https://docs.python.org/3.14/library/sys.html#module-sys) attributes for the configuration, going beyond just [`sys.argv`](https://docs.python.org/3.14/library/sys.html#sys.argv). Victor Stinner contributed the patch.
