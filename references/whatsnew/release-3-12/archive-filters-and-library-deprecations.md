# What’s New In Python 3.12 / Deprecated - collections.abc, importlib, sys, tarfile, typing, xml.etree.elementtree

[`sys`](https://docs.python.org/3.14/library/sys.html#module-sys): The trio of fields [`sys.last_type`](https://docs.python.org/3.14/library/sys.html#sys.last_type), [`sys.last_value`](https://docs.python.org/3.14/library/sys.html#sys.last_value) and [`sys.last_traceback`](https://docs.python.org/3.14/library/sys.html#sys.last_traceback) now carry a deprecation. Reach for [`sys.last_exc`](https://docs.python.org/3.14/library/sys.html#sys.last_exc) as the replacement. (Contributed by Irit Katriel in [gh-102778](https://github.com/python/cpython/issues/102778).)

- [`tarfile`](https://docs.python.org/3.14/library/tarfile.html#module-tarfile): Pulling tar archives apart without naming a *filter* carries a deprecation through Python 3.14, the release that promotes `'data'` to the default filter. Consult [Extraction filters](https://docs.python.org/3.14/library/tarfile.html#tarfile-extraction-filter) for the specifics.

- [`typing`](https://docs.python.org/3.14/library/typing.html#module-typing):

  - [`typing.Hashable`](https://docs.python.org/3.14/library/typing.html#typing.Hashable) along with [`typing.Sized`](https://docs.python.org/3.14/library/typing.html#typing.Sized) ? both standing in for [`collections.abc.Hashable`](https://docs.python.org/3.14/library/collections.abc.html#collections.abc.Hashable) and [`collections.abc.Sized`](https://docs.python.org/3.14/library/collections.abc.html#collections.abc.Sized) in turn ? now carry deprecations. ([gh-94309](https://github.com/python/cpython/issues/94309).)

  - [`typing.ByteString`](https://docs.python.org/3.14/library/typing.html#typing.ByteString), which had a deprecation dating back to Python 3.9, will from now on trigger a [`DeprecationWarning`](https://docs.python.org/3.14/library/exceptions.html#DeprecationWarning) whenever it is referenced. (Contributed by Alex Waygood in [gh-91896](https://github.com/python/cpython/issues/91896).)

- [`xml.etree.ElementTree`](https://docs.python.org/3.14/library/xml.etree.elementtree.html#module-xml.etree.ElementTree): Checking the truth value of an [`xml.etree.ElementTree.Element`](https://docs.python.org/3.14/library/xml.etree.elementtree.html#xml.etree.ElementTree.Element) now triggers a [`DeprecationWarning`](https://docs.python.org/3.14/library/exceptions.html#DeprecationWarning) from this module. Previously that scenario produced a [`FutureWarning`](https://docs.python.org/3.14/library/exceptions.html#FutureWarning) under the Python implementation, while the C build stayed silent. (Contributed by Jacob Walls in [gh-83122](https://github.com/python/cpython/issues/83122).)

- The three-argument forms (type, value, traceback) belonging to [`coroutine throw()`](https://docs.python.org/3.14/reference/datamodel.html#coroutine.throw), [`generator throw()`](https://docs.python.org/3.14/reference/expressions.html#generator.throw) and [`async generator throw()`](https://docs.python.org/3.14/reference/expressions.html#agen.athrow) now carry deprecations and might disappear in some later Python release. Switch to the single-argument forms of these calls. (Contributed by Ofey Chan in [gh-89874](https://github.com/python/cpython/issues/89874).)

- A [`DeprecationWarning`](https://docs.python.org/3.14/library/exceptions.html#DeprecationWarning) now fires whenever a module's [`__package__`](https://docs.python.org/3.14/reference/datamodel.html#module.__package__) fails to match [`__spec__.parent`](https://docs.python.org/3.14/library/importlib.html#importlib.machinery.ModuleSpec.parent) (the earlier behavior raised [`ImportWarning`](https://docs.python.org/3.14/library/exceptions.html#ImportWarning)). (Contributed by Brett Cannon in [gh-65961](https://github.com/python/cpython/issues/65961).)

- Assigning [`__package__`](https://docs.python.org/3.14/reference/datamodel.html#module.__package__) or [`__cached__`](https://docs.python.org/3.14/reference/datamodel.html#module.__cached__) onto a module now carries a deprecation; the import machinery in Python 3.14 will no longer assign or consult either. (Contributed by Brett Cannon in [gh-65961](https://github.com/python/cpython/issues/65961).)

- Applying the bitwise inversion operator (`~`) to a bool now carries a deprecation. Python 3.16 will turn this into an error. For logical negation of bools, reach for `not` in its place. Should you genuinely require the bitwise inversion of the backing `int`, perform an explicit int conversion: `~int(x)`. (Contributed by Tim Hoffmann in [gh-103487](https://github.com/python/cpython/issues/103487).)

- Reading [`co_lnotab`](https://docs.python.org/3.14/reference/datamodel.html#codeobject.co_lnotab) off of code objects picked up its deprecation back in Python 3.10 by way of [**PEP 626**](https://peps.python.org/pep-0626/), yet a real [`DeprecationWarning`](https://docs.python.org/3.14/library/exceptions.html#DeprecationWarning) only arrived in 3.12. Could go away in 3.15. (Contributed by Nikita Sobolev in [gh-101866](https://github.com/python/cpython/issues/101866).)
