# What's New In Python 3.4 / Changes in the Python API — base64, binascii, cmath, functools, http.client, importlib, inspect, py_compile, ssl, sys

### Changes in the Python API

- The ABCs declared in [`importlib.abc`](https://docs.python.org/3.14/library/importlib.html#module-importlib.abc) now either throw the fitting exception or hand back a default value rather than blindly throwing [`NotImplementedError`](https://docs.python.org/3.14/library/exceptions.html#NotImplementedError). The only code touched is that which calls [`super()`](https://docs.python.org/3.14/library/functions.html#super) and cascades the whole way down to the ABCs. To stay compatible, trap either `NotImplementedError` or the fitting exception as the case requires.

- By default the module type now sets its [`__package__`](https://docs.python.org/3.14/reference/datamodel.html#module.__package__) and [`__loader__`](https://docs.python.org/3.14/reference/datamodel.html#module.__loader__) attributes to `None`. For a backwards-compatible way of checking whether these attributes were assigned, write something such as `getattr(module, '__loader__', None) is not None`. ([bpo-17115](https://bugs.python.org/issue?@action=redirect&bpo=17115).)

- To make reloading work correctly, `importlib.util.module_for_loader()` now assigns `__loader__` and `__package__` no matter what. Should that be unwanted, you must assign these attributes by hand. For managing modules you may turn to `importlib.util.module_to_load()`.

- On a reload, import now resets the pertinent attributes (such as `__name__`, `__loader__`, `__package__`, `__file__`, `__cached__`) no matter what. Be aware this brings back a pre-3.3 behavior, meaning a reloaded module gets re-found ([bpo-19413](https://bugs.python.org/issue?@action=redirect&bpo=19413)).

- Frozen packages have stopped setting `__path__` to a list holding the package name; they now set it to an empty list. Under the old behavior the import system could misbehave on submodule imports whenever a directory shared its name with the frozen package. To learn whether a module is a package, the right approach is `hasattr(module, '__path__')` ([bpo-18065](https://bugs.python.org/issue?@action=redirect&bpo=18065)).

- Frozen modules have stopped defining a `__file__` attribute. Setting it is semantically wrong for frozen modules, since they load from no explicit place. When you really must confirm that a module originates from frozen code, you can test whether the module's `__spec__.location` equals `'frozen'`, check that the loader subclasses [`importlib.machinery.FrozenImporter`](https://docs.python.org/3.14/library/importlib.html#importlib.machinery.FrozenImporter), or, where Python 2 compatibility matters, fall back on `imp.is_frozen()`.

- [`py_compile.compile()`](https://docs.python.org/3.14/library/py_compile.html#py_compile.compile) now throws [`FileExistsError`](https://docs.python.org/3.14/library/exceptions.html#FileExistsError) whenever its destination file path is a symlink or some non-regular file. The point is to flag that import would clobber such files with an ordinary file regardless of the original file path's type.

- [`importlib.abc.SourceLoader.get_source()`](https://docs.python.org/3.14/library/importlib.html#importlib.abc.SourceLoader.get_source) has stopped throwing [`ImportError`](https://docs.python.org/3.14/library/exceptions.html#ImportError) whenever the source being loaded provokes a [`SyntaxError`](https://docs.python.org/3.14/library/exceptions.html#SyntaxError) or [`UnicodeDecodeError`](https://docs.python.org/3.14/library/exceptions.html#UnicodeDecodeError). Given that `ImportError` belongs only to the case where source ought to exist yet cannot be found, overloading it for source that is found but malformed felt excessive. If your earlier code caught ImportError and you want to go on ignoring syntax or decoding problems, trap all three exceptions from now on.

- [`functools.update_wrapper()`](https://docs.python.org/3.14/library/functools.html#functools.update_wrapper) along with [`functools.wraps()`](https://docs.python.org/3.14/library/functools.html#functools.wraps) now properly point the `__wrapped__` attribute at the wrapped function, even when that function carried its own `__wrapped__` attribute. The result is that `__wrapped__` attributes now properly chain a stack of decorated functions, instead of each `__wrapped__` attribute in the chain pointing at the innermost function. Any introspection library that treated the former behavior as deliberate can call [`inspect.unwrap()`](https://docs.python.org/3.14/library/inspect.html#inspect.unwrap) to reach the first function in the chain lacking a `__wrapped__` attribute.

- [`inspect.getfullargspec()`](https://docs.python.org/3.14/library/inspect.html#inspect.getfullargspec) is now built atop [`inspect.signature()`](https://docs.python.org/3.14/library/inspect.html#inspect.signature) and so copes with a far broader range of callable objects than before. Over the span of the Python 3.4 series, more builtin and extension-module callables are anticipated to acquire signature metadata. Any code presuming that `inspect.getfullargspec()` will choke on non-Python callables might require revision to suit.

- [`importlib.machinery.PathFinder`](https://docs.python.org/3.14/library/importlib.html#importlib.machinery.PathFinder) now forwards the present working directory to the objects in [`sys.path_hooks`](https://docs.python.org/3.14/library/sys.html#sys.path_hooks) in place of the empty string. Consequently [`sys.path_importer_cache`](https://docs.python.org/3.14/library/sys.html#sys.path_importer_cache) never holds `''`, so walking `sys.path_importer_cache` by way of [`sys.path`](https://docs.python.org/3.14/library/sys.html#sys.path) will miss certain keys. A module's `__file__` will now likewise carry an absolute path when it is imported from the present working directory, including under `-m` with the interpreter (the lone exception being `__main__.__file__` whenever some script was launched directly by way of a path that is relative) (Contributed by Brett Cannon in [bpo-18416](https://bugs.python.org/issue?@action=redirect&bpo=18416)). gets given at the command-line) ([bpo-18416](https://bugs.python.org/issue?@action=redirect&bpo=18416)).

- Dropping the *strict* parameter from [`HTTPConnection`](https://docs.python.org/3.14/library/http.client.html#http.client.HTTPConnection) and [`HTTPSConnection`](https://docs.python.org/3.14/library/http.client.html#http.client.HTTPSConnection) shifts what the leftover arguments mean if you pass them positionally rather than by keyword. Provided you have heeded deprecation warnings, your code should already be handing any extra arguments over as keywords.

- A string sitting between `from __future__ import ...` statements now *always* throws a [`SyntaxError`](https://docs.python.org/3.14/library/exceptions.html#SyntaxError). Formerly, absent a leading docstring, such an in-between string would occasionally be passed over. This aligns CPython with the language spec; Jython and PyPy already conformed. ([bpo-17434](https://bugs.python.org/issue?@action=redirect&bpo=17434)).

- [`ssl.SSLSocket.getpeercert()`](https://docs.python.org/3.14/library/ssl.html#ssl.SSLSocket.getpeercert) and [`ssl.SSLSocket.do_handshake()`](https://docs.python.org/3.14/library/ssl.html#ssl.SSLSocket.do_handshake) now throw an [`OSError`](https://docs.python.org/3.14/library/exceptions.html#OSError) carrying `ENOTCONN` whenever the `SSLSocket` is unconnected, supplanting the old behavior of throwing an [`AttributeError`](https://docs.python.org/3.14/library/exceptions.html#AttributeError). On top of that, `getpeercert()` will throw a [`ValueError`](https://docs.python.org/3.14/library/exceptions.html#ValueError) when the handshake remains undone.

- [`base64.b32decode()`](https://docs.python.org/3.14/library/base64.html#base64.b32decode) now throws a [`binascii.Error`](https://docs.python.org/3.14/library/binascii.html#binascii.Error) whenever the input string holds characters outside the b32 alphabet, in place of a [`TypeError`](https://docs.python.org/3.14/library/exceptions.html#TypeError). That specific `TypeError` slipped through when the rest of the `TypeError`s were converted. (Contributed by Serhiy Storchaka in [bpo-18011](https://bugs.python.org/issue?@action=redirect&bpo=18011).) Note: this same change made its way into Python 3.3.3 by accident.

- The `file` attribute now closes itself automatically once the `cgi.FieldStorage` instance that created it is garbage collected. Should you have been extracting the file object apart from the `cgi.FieldStorage` instance without keeping that instance alive, you ought to either hold on to the whole `cgi.FieldStorage` instance or read the file's contents before the `cgi.FieldStorage` instance gets garbage collected.

- Invoking `read` or `write` against a closed SSL socket now throws an explanatory [`ValueError`](https://docs.python.org/3.14/library/exceptions.html#ValueError) in place of the formerly more puzzling [`AttributeError`](https://docs.python.org/3.14/library/exceptions.html#AttributeError) ([bpo-9177](https://bugs.python.org/issue?@action=redirect&bpo=9177)).

- [`slice.indices()`](https://docs.python.org/3.14/reference/datamodel.html#slice.indices) has stopped raising an [`OverflowError`](https://docs.python.org/3.14/library/exceptions.html#OverflowError) on enormous values. A side effect of this fix is that `slice.indices()` now raises a [`ValueError`](https://docs.python.org/3.14/library/exceptions.html#ValueError) when handed a negative length; formerly it returned meaningless values ([bpo-14794](https://bugs.python.org/issue?@action=redirect&bpo=14794)).

- Unlike the [`cmath`](https://docs.python.org/3.14/library/cmath.html#module-cmath) functions, the [`complex`](https://docs.python.org/3.14/library/functions.html#complex) constructor was wrongly tolerating [`float`](https://docs.python.org/3.14/library/functions.html#float) values whenever an object's `__complex__` special method handed one back. That now raises a [`TypeError`](https://docs.python.org/3.14/library/exceptions.html#TypeError). ([bpo-16290](https://bugs.python.org/issue?@action=redirect&bpo=16290).)

- Across 3.2 and 3.3 the [`int`](https://docs.python.org/3.14/library/functions.html#int) constructor mistakenly tolerated [`float`](https://docs.python.org/3.14/library/functions.html#float) values for its *base* parameter. Few people are likely to have done so, but where they did it now raises a [`TypeError`](https://docs.python.org/3.14/library/exceptions.html#TypeError) ([bpo-16772](https://bugs.python.org/issue?@action=redirect&bpo=16772)).

-

Defaults belonging to keyword-only arguments now get evaluated *after* the defaults for ordinary keyword arguments, not beforehand. With luck nobody authored code that leans on the old buggy behavior ([bpo-16967](https://bugs.python.org/issue?@action=redirect&bpo=16967)).

- Lingering thread states now get cleared following [`fork()`](https://docs.python.org/3.14/library/os.html#os.fork). This may free certain system resources that formerly stayed wrongly alive forever (database connections held in thread-local storage, say). ([bpo-17094](https://bugs.python.org/issue?@action=redirect&bpo=17094).)

- Parameter names within `__annotations__` dicts now get mangled properly, on a par with [`__kwdefaults__`](https://docs.python.org/3.14/reference/datamodel.html#function.__kwdefaults__). (Contributed by Yury Selivanov in [bpo-20625](https://bugs.python.org/issue?@action=redirect&bpo=20625).)

- [`hashlib.hash.name`](https://docs.python.org/3.14/library/hashlib.html#hashlib.hash.name) now consistently hands back the identifier in lower case. A few builtin hashes formerly had uppercase names, but with the interface now formally public the naming was made uniform ([bpo-18532](https://bugs.python.org/issue?@action=redirect&bpo=18532)).

- Since [`unittest.TestSuite`](https://docs.python.org/3.14/library/unittest.html#unittest.TestSuite) now releases references to tests once they have run, any test harness that reuses a [`TestSuite`](https://docs.python.org/3.14/library/unittest.html#unittest.TestSuite) to rerun a batch of tests may break. Reusing test suites in this way is inadvisable, because it carries state across test runs and so undermines the test isolation [`unittest`](https://docs.python.org/3.14/library/unittest.html#module-unittest) aims to deliver. Still, if losing that isolation is tolerable, you can recover the former behavior by subclassing `TestSuite` with a `_removeTestAtIndex` method that is a no-op (refer to [`TestSuite.__iter__()`](https://docs.python.org/3.14/library/unittest.html#unittest.TestSuite.__iter__)) ([bpo-11798](https://bugs.python.org/issue?@action=redirect&bpo=11798)).

- [`unittest`](https://docs.python.org/3.14/library/unittest.html#module-unittest) now relies on [`argparse`](https://docs.python.org/3.14/library/argparse.html#module-argparse) to parse the command line. Some invalid command forms that formerly worked are now rejected; this should not in theory raise backward compatibility concerns, given that the rejected command forms made no sense and are improbable to be in use.

-

Whenever the string being matched is a [bytes-like object](https://docs.python.org/3.14/glossary.html#term-bytes-like-object), the [`re.split()`](https://docs.python.org/3.14/library/re.html#re.split), [`re.findall()`](https://docs.python.org/3.14/library/re.html#re.findall), and [`re.sub()`](https://docs.python.org/3.14/library/re.html#re.sub) functions — together with the [`group()`](https://docs.python.org/3.14/library/re.html#re.Match.group) and [`groups()`](https://docs.python.org/3.14/library/re.html#re.Match.groups) methods on `match` objects — now hand back a *bytes* object every time. Up to now the returned type tracked the input type, so any code that counted on getting back, for instance, a `bytearray` will have to be reworked.

- Hand a string to the `audioop` functions and they now error out on the spot, rather than breaking unpredictably somewhere down the line ([bpo-16685](https://bugs.python.org/issue?@action=redirect&bpo=16685)).

- For backward compatibility the freshly added *convert_charrefs* argument on [`HTMLParser`](https://docs.python.org/3.14/library/html.parser.html#html.parser.HTMLParser) defaults to `False` for now, though down the road its default is slated to flip to `True`. The advice is to supply this keyword, set to whatever value you want, on every `HTMLParser` call throughout your code ([bpo-13633](https://bugs.python.org/issue?@action=redirect&bpo=13633)).

- Because the *digestmod* argument on the [`hmac.new()`](https://docs.python.org/3.14/library/hmac.html#hmac.new) function is set to lose its default later on, every `hmac.new()` call ought to be updated to name a *digestmod* outright ([bpo-17276](https://bugs.python.org/issue?@action=redirect&bpo=17276)).

- Passing the `SO` key into [`sysconfig.get_config_var()`](https://docs.python.org/3.14/library/sysconfig.html#sysconfig.get_config_var), or fetching `SO` out of what [`sysconfig.get_config_vars()`](https://docs.python.org/3.14/library/sysconfig.html#sysconfig.get_config_vars) returns, is now deprecated. Swap that key for either `EXT_SUFFIX` or `SHLIB_SUFFIX`, whichever fits the situation ([bpo-19555](https://bugs.python.org/issue?@action=redirect&bpo=19555)).

- Wherever `open` functions are invoked with `U`, those calls need fixing. Under Python3 the `U` does nothing and is destined to throw an error once used. To reproduce the old Python2 behavior — depending on which function it is — reach for a *newline* argument, or where that falls short, wrap the stream in a [`TextIOWrapper`](https://docs.python.org/3.14/library/io.html#io.TextIOWrapper) and lean on its *newline* argument ([bpo-15204](https://bugs.python.org/issue?@action=redirect&bpo=15204)).

- Driving `pyvenv` from a script while wanting pip left *out* means you have to tack `--without-pip` onto how you call it.

- With an indent supplied, the out-of-the-box conduct of [`json.dump()`](https://docs.python.org/3.14/library/json.html#json.dump) and [`json.dumps()`](https://docs.python.org/3.14/library/json.html#json.dumps) is now different: trailing spaces no longer appear after the item-separating commas that end each line. The only place this bites is in tests running white-space-sensitive comparisons over such output ([bpo-16333](https://bugs.python.org/issue?@action=redirect&bpo=16333)).

- Because [`doctest`](https://docs.python.org/3.14/library/doctest.html#module-doctest) now hunts for doctests inside extension module `__doc__` strings, a discovery run that sweeps in extension modules holding doctest-looking content may surface test failures you have never run into before ([bpo-3158](https://bugs.python.org/issue?@action=redirect&bpo=3158)).

- As part of the work to speed up Python startup, the [`collections.abc`](https://docs.python.org/3.14/library/collections.abc.html#module-collections.abc) module saw a light refactor. One upshot is that pulling in [`collections`](https://docs.python.org/3.14/library/collections.html#module-collections) no longer drags `collections.abc` in along with it. Any program that leaned on that (undocumented) implicit import must now spell out `import collections.abc` for itself ([bpo-20784](https://bugs.python.org/issue?@action=redirect&bpo=20784)).
