# What's New In Python 3.7 / Changes in the Python API

### Changes in the Python API

- [`socketserver.ThreadingMixIn.server_close`](https://docs.python.org/3.14/library/socketserver.html#socketserver.BaseServer.server_close) henceforth blocks until every non-daemon thread has finished. Assign `False` to the freshly added [`socketserver.ThreadingMixIn.block_on_close`](https://docs.python.org/3.14/library/socketserver.html#socketserver.ThreadingMixIn.block_on_close) class attribute to recover the pre-3.7 behaviour. Victor Stinner authored this — see [bpo-31233](https://bugs.python.org/issue?@action=redirect&bpo=31233) and [bpo-33540](https://bugs.python.org/issue?@action=redirect&bpo=33540).

- [`socketserver.ForkingMixIn.server_close`](https://docs.python.org/3.14/library/socketserver.html#socketserver.BaseServer.server_close) henceforth blocks until every child process has finished. Assign `False` to the freshly added [`socketserver.ForkingMixIn.block_on_close`](https://docs.python.org/3.14/library/socketserver.html#socketserver.ThreadingMixIn.block_on_close) class attribute to recover the pre-3.7 behaviour. Victor Stinner authored this — see [bpo-31151](https://bugs.python.org/issue?@action=redirect&bpo=31151) and [bpo-33540](https://bugs.python.org/issue?@action=redirect&bpo=33540).

- The [`locale.localeconv()`](https://docs.python.org/3.14/library/locale.html#locale.localeconv) function will now, under certain conditions, momentarily switch the `LC_CTYPE` locale over to whatever `LC_NUMERIC` holds. Victor Stinner contributed this through [bpo-31900](https://bugs.python.org/issue?@action=redirect&bpo=31900).

- [`pkgutil.walk_packages()`](https://docs.python.org/3.14/library/pkgutil.html#pkgutil.walk_packages) henceforth raises a [`ValueError`](https://docs.python.org/3.14/library/exceptions.html#ValueError) when *path* happens to be a string. Formerly it just handed back an empty list. Sanyam Khurana landed this via [bpo-24744](https://bugs.python.org/issue?@action=redirect&bpo=24744).

- A format string passed to [`string.Formatter.format()`](https://docs.python.org/3.14/library/string.html#string.Formatter.format) is now treated as [positional-only](https://docs.python.org/3.14/glossary.html#positional-only-parameter). Supplying it by keyword had been deprecated back in Python 3.5. Serhiy Storchaka handled this in [bpo-29193](https://bugs.python.org/issue?@action=redirect&bpo=29193).

- The attributes [`key`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel.key), [`value`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel.value) and [`coded_value`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel.coded_value) belonging to the [`http.cookies.Morsel`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel) class have become read-only. Writing to them was deprecated as far back as Python 3.5. Reach instead for the [`set()`](https://docs.python.org/3.14/library/http.cookies.html#http.cookies.Morsel.set) method to assign them. Serhiy Storchaka shipped this in [bpo-29192](https://bugs.python.org/issue?@action=redirect&bpo=29192).

- The *mode* argument given to [`os.makedirs()`](https://docs.python.org/3.14/library/os.html#os.makedirs) no longer touches the file permission bits of any freshly created intermediate-level directories. Should you wish to fix their permission bits, configure the umask ahead of calling `makedirs()`. Serhiy Storchaka contributed this via [bpo-19930](https://bugs.python.org/issue?@action=redirect&bpo=19930).

- The [`struct.Struct.format`](https://docs.python.org/3.14/library/struct.html#struct.Struct.format) type is from now on [`str`](https://docs.python.org/3.14/library/stdtypes.html#str) rather than [`bytes`](https://docs.python.org/3.14/library/stdtypes.html#bytes). Victor Stinner landed this through [bpo-21071](https://bugs.python.org/issue?@action=redirect&bpo=21071).

- `cgi.parse_multipart()` henceforth takes the *encoding* and *errors* arguments and yields output matching `FieldStorage`: for fields that are not files, the value tied to a key comes back as a list of strings rather than bytes. Pierre Quentel added this in [bpo-29979](https://bugs.python.org/issue?@action=redirect&bpo=29979).

- Owing to internal reworking within [`socket`](https://docs.python.org/3.14/library/socket.html#module-socket), invoking [`socket.fromshare()`](https://docs.python.org/3.14/library/socket.html#socket.fromshare) against a socket produced by [`socket.share`](https://docs.python.org/3.14/library/socket.html#socket.socket.share) under earlier Python releases is unsupported.

- `repr` for [`BaseException`](https://docs.python.org/3.14/library/exceptions.html#BaseException) was adjusted so it omits the trailing comma. The bulk of exceptions feel this change. Serhiy Storchaka handled it in [bpo-30399](https://bugs.python.org/issue?@action=redirect&bpo=30399).

- `repr` for [`datetime.timedelta`](https://docs.python.org/3.14/library/datetime.html#datetime.timedelta) was adjusted so the keyword arguments appear in its output. Utkarsh Upadhyay shipped this in [bpo-30302](https://bugs.python.org/issue?@action=redirect&bpo=30302).

- Since [`shutil.rmtree()`](https://docs.python.org/3.14/library/shutil.html#shutil.rmtree) is at this point built atop the [`os.scandir()`](https://docs.python.org/3.14/library/os.html#os.scandir) function, the caller-supplied *onerror* handler now receives `os.scandir` as its first argument rather than `os.listdir` whenever enumerating the directory fails.

- Down the road, support for nested sets together with set operations inside regular expressions, following [Unicode Technical Standard #18](https://unicode.org/reports/tr18/), may arrive. Such an addition would shift the syntax. So that this eventual change goes smoothly, for now a [`FutureWarning`](https://docs.python.org/3.14/library/exceptions.html#FutureWarning) gets raised whenever a case is ambiguous. That covers sets opening with a literal `'['` or holding literal character runs `'--'`, `'&&'`, `'~~'`, and `'||'`. Prefix them with a backslash to suppress the warning. Serhiy Storchaka contributed this via [bpo-30349](https://bugs.python.org/issue?@action=redirect&bpo=30349).

- What you get from splitting a string against a [`regular expression`](https://docs.python.org/3.14/library/re.html#module-re) capable of matching an empty string has shifted. As an illustration, splitting on `r'\s*'` will at this point split not merely on whitespace the way it once did, but additionally on empty strings ahead of every non-whitespace character and right before the string ends. To bring back the old behavior, swap the pattern to `r'\s+'`. Since Python 3.5 such patterns triggered a [`FutureWarning`](https://docs.python.org/3.14/library/exceptions.html#FutureWarning).

When a pattern lines up with both empty and non-empty strings, what searching for every match returns may shift in additional situations as well. To illustrate, within the string `'a\n\n'`, the pattern `r'(?m)^\s*?$'` will not merely match empty strings at positions 2 and 3, but will also match the string `'\n'` at positions 2–3. So that only blank lines match, the pattern ought to be recast as `r'(?m)^[^\S\n]*$'`.

[`re.sub()`](https://docs.python.org/3.14/library/re.html#re.sub) at this point substitutes empty matches that sit next to an earlier non-empty match. To illustrate, `re.sub('x*', '-', 'abxd')` now hands back `'-a-b--d-'` in place of `'-a-b-d-'` (the leading minus between "b" and "d" stands in for "x", while the trailing minus stands in for an empty string between "x" and "d").

Serhiy Storchaka delivered this - refer to [bpo-25054](https://bugs.python.org/issue?@action=redirect&bpo=25054) and [bpo-32308](https://bugs.python.org/issue?@action=redirect&bpo=32308).

- Adjust [`re.escape()`](https://docs.python.org/3.14/library/re.html#re.escape) such that it escapes only the regex special characters rather than escaping everything aside from ASCII letters, numbers, and `'_'`. Serhiy Storchaka contributed this in [bpo-29995](https://bugs.python.org/issue?@action=redirect&bpo=29995).

- [`tracemalloc.Traceback`](https://docs.python.org/3.14/library/tracemalloc.html#tracemalloc.Traceback) frames are at present ordered oldest first through most recent, lining up better with [`traceback`](https://docs.python.org/3.14/library/traceback.html#module-traceback). Jesse Bakker shipped this in [bpo-32121](https://bugs.python.org/issue?@action=redirect&bpo=32121).

- Across OSes that offer the [`socket.SOCK_NONBLOCK`](https://docs.python.org/3.14/library/socket.html#socket.SOCK_NONBLOCK) or [`socket.SOCK_CLOEXEC`](https://docs.python.org/3.14/library/socket.html#socket.SOCK_CLOEXEC) bit flags, the [`socket.type`](https://docs.python.org/3.14/library/socket.html#socket.socket.type) no longer carries them. As a result, tests such as `if sock.type == socket.SOCK_STREAM` behave correctly on every platform. Yury Selivanov contributed this through [bpo-32331](https://bugs.python.org/issue?@action=redirect&bpo=32331).

- Under Windows the default value for the *close_fds* argument of [`subprocess.Popen`](https://docs.python.org/3.14/library/subprocess.html#subprocess.Popen) flipped from [`False`](https://docs.python.org/3.14/library/constants.html#False) to [`True`](https://docs.python.org/3.14/library/constants.html#True) whenever the standard handles get redirected. Had you formerly relied on handles being inherited while running `subprocess.Popen` together with standard io redirection, you must now hand it `close_fds=False` to retain the old behaviour, or else turn to [`STARTUPINFO.lpAttributeList`](https://docs.python.org/3.14/library/subprocess.html#subprocess.STARTUPINFO.lpAttributeList).

- [`importlib.machinery.PathFinder.invalidate_caches()`](https://docs.python.org/3.14/library/importlib.html#importlib.machinery.PathFinder.invalidate_caches) — which by extension shapes [`importlib.invalidate_caches()`](https://docs.python.org/3.14/library/importlib.html#importlib.invalidate_caches) — at present drops entries within [`sys.path_importer_cache`](https://docs.python.org/3.14/library/sys.html#sys.path_importer_cache) whose value is `None`. Brett Cannon contributed this via [bpo-33169](https://bugs.python.org/issue?@action=redirect&bpo=33169).

- Within [`asyncio`](https://docs.python.org/3.14/library/asyncio.html#module-asyncio), the methods [`loop.sock_recv()`](https://docs.python.org/3.14/library/asyncio-eventloop.html#asyncio.loop.sock_recv), [`loop.sock_sendall()`](https://docs.python.org/3.14/library/asyncio-eventloop.html#asyncio.loop.sock_sendall), [`loop.sock_accept()`](https://docs.python.org/3.14/library/asyncio-eventloop.html#asyncio.loop.sock_accept), [`loop.getaddrinfo()`](https://docs.python.org/3.14/library/asyncio-eventloop.html#asyncio.loop.getaddrinfo), [`loop.getnameinfo()`](https://docs.python.org/3.14/library/asyncio-eventloop.html#asyncio.loop.getnameinfo) were turned into genuine coroutine methods so they align with how they are documented. Formerly, those methods returned [`asyncio.Future`](https://docs.python.org/3.14/library/asyncio-future.html#asyncio.Future) instances. Yury Selivanov contributed this through [bpo-32327](https://bugs.python.org/issue?@action=redirect&bpo=32327).

- [`asyncio.Server.sockets`](https://docs.python.org/3.14/library/asyncio-eventloop.html#asyncio.Server.sockets) at present hands back a copy of the internal server-socket list rather than passing the list along directly. Yury Selivanov contributed this through [bpo-32662](https://bugs.python.org/issue?@action=redirect&bpo=32662).

- [`Struct.format`](https://docs.python.org/3.14/library/struct.html#struct.Struct.format) is at this point a [`str`](https://docs.python.org/3.14/library/stdtypes.html#str) object in place of a [`bytes`](https://docs.python.org/3.14/library/stdtypes.html#bytes) object. Victor Stinner landed this through [bpo-21071](https://bugs.python.org/issue?@action=redirect&bpo=21071).

- [`argparse`](https://docs.python.org/3.14/library/argparse.html#module-argparse) subparsers can at present be marked mandatory by handing `required=True` to [`ArgumentParser.add_subparsers()`](https://docs.python.org/3.14/library/argparse.html#argparse.ArgumentParser.add_subparsers). Anthony Sottile contributed this through [bpo-26510](https://bugs.python.org/issue?@action=redirect&bpo=26510).

- [`ast.literal_eval()`](https://docs.python.org/3.14/library/ast.html#ast.literal_eval) has grown stricter. Adding or subtracting arbitrary numbers is from now on disallowed. Serhiy Storchaka contributed this via [bpo-31778](https://bugs.python.org/issue?@action=redirect&bpo=31778).

- [`Calendar.itermonthdates`](https://docs.python.org/3.14/library/calendar.html#calendar.Calendar.itermonthdates) will at present reliably throw an exception whenever a date lands beyond the `0001-01-01` through `9999-12-31` span. For applications unable to cope with such exceptions, the newly added [`Calendar.itermonthdays3`](https://docs.python.org/3.14/library/calendar.html#calendar.Calendar.itermonthdays3) and [`Calendar.itermonthdays4`](https://docs.python.org/3.14/library/calendar.html#calendar.Calendar.itermonthdays4) are available. Those new methods yield tuples and are not bounded by the span that [`datetime.date`](https://docs.python.org/3.14/library/datetime.html#datetime.date) covers. Alexander Belopolsky contributed this through [bpo-28292](https://bugs.python.org/issue?@action=redirect&bpo=28292).

- [`collections.ChainMap`](https://docs.python.org/3.14/library/collections.html#collections.ChainMap) at present keeps the ordering of the mappings beneath it. Raymond Hettinger contributed this through [bpo-32792](https://bugs.python.org/issue?@action=redirect&bpo=32792).

- The `submit()` method on [`concurrent.futures.ThreadPoolExecutor`](https://docs.python.org/3.14/library/concurrent.futures.html#concurrent.futures.ThreadPoolExecutor) and on [`concurrent.futures.ProcessPoolExecutor`](https://docs.python.org/3.14/library/concurrent.futures.html#concurrent.futures.ProcessPoolExecutor) at present throws a [`RuntimeError`](https://docs.python.org/3.14/library/exceptions.html#RuntimeError) whenever it is invoked while the interpreter is shutting down. Mark Nemec contributed this through [bpo-33097](https://bugs.python.org/issue?@action=redirect&bpo=33097).

- The [`configparser.ConfigParser`](https://docs.python.org/3.14/library/configparser.html#configparser.ConfigParser) constructor at present leans on `read_dict()` while handling the default values, so its behavior matches the remainder of the parser. Keys and values in the defaults dictionary that are not strings now get silently coerced into strings. James Tocknell contributed this through [bpo-23835](https://bugs.python.org/issue?@action=redirect&bpo=23835).

- A number of undocumented internal imports went away. For one, `os.errno` can no longer be reached; just write `import errno` on its own instead. Bear in mind that such undocumented internal imports are liable to vanish at any moment without warning, even within micro version releases.
