# Python 2.7 changes: ctypes, datetime and related standard-library changes

The [`ctypes`](https://docs.python.org/3.14/library/ctypes.html#module-ctypes) module now consistently turns `None` into a C `NULL` pointer for any argument that is declared as a pointer. (Changed by Thomas Heller; [bpo-4606](https://bugs.python.org/issue?@action=redirect&bpo=4606).) The supporting [libffi library](https://sourceware.org/libffi/) has been bumped to version 3.0.9, which brings a range of fixes across various platforms. (Updated by Matthias Klose; [bpo-8142](https://bugs.python.org/issue?@action=redirect&bpo=8142).)

- New method: the [`timedelta`](https://docs.python.org/3.14/library/datetime.html#datetime.timedelta) class in the [`datetime`](https://docs.python.org/3.14/library/datetime.html#module-datetime) module has gained a [`total_seconds()`](https://docs.python.org/3.14/library/datetime.html#datetime.timedelta.total_seconds) method that yields the count of seconds within the duration. (Contributed by Brian Quinlan; [bpo-5788](https://bugs.python.org/issue?@action=redirect&bpo=5788).)

- New method: the [`Decimal`](https://docs.python.org/3.14/library/decimal.html#decimal.Decimal) class has gained a [`from_float()`](https://docs.python.org/3.14/library/decimal.html#decimal.Decimal.from_float) class method that carries out an exact conversion from a floating-point number into a `Decimal`. That exact conversion aims for the nearest decimal approximation of the value held by the floating-point representation; as a result, the produced decimal value still carries whatever inaccuracy was present. As an illustration, `Decimal.from_float(0.1)` yields `Decimal('0.1000000000000000055511151231257827021181583404541015625')`. (Implemented by Raymond Hettinger; [bpo-4796](https://bugs.python.org/issue?@action=redirect&bpo=4796).)

Comparing [`Decimal`](https://docs.python.org/3.14/library/decimal.html#decimal.Decimal) instances against floating-point numbers now yields sensible outcomes grounded in the numeric values of the operands. Earlier, such comparisons would default to Python's standard object-comparison rules, which gave arbitrary outcomes determined by the type. Bear in mind that you still can't mix `Decimal` and floating point within other operations like addition, because you ought to be deciding explicitly how the conversion between float and `Decimal` should happen. (Fixed by Mark Dickinson; [bpo-2531](https://bugs.python.org/issue?@action=redirect&bpo=2531).)

The [`Decimal`](https://docs.python.org/3.14/library/decimal.html#decimal.Decimal) constructor will now accept floating-point numbers (a change made by Raymond Hettinger; [bpo-8257](https://bugs.python.org/issue?@action=redirect&bpo=8257)), along with non-European Unicode characters like Arabic-Indic digits (a feature from Mark Dickinson; [bpo-6595](https://bugs.python.org/issue?@action=redirect&bpo=6595)).

Most methods belonging to the [`Context`](https://docs.python.org/3.14/library/decimal.html#decimal.Context) class now take integers in addition to [`Decimal`](https://docs.python.org/3.14/library/decimal.html#decimal.Decimal) instances; the sole exceptions being the [`canonical()`](https://docs.python.org/3.14/library/decimal.html#decimal.Context.canonical) and [`is_canonical()`](https://docs.python.org/3.14/library/decimal.html#decimal.Context.is_canonical) methods. (Patch by Juan José Conti; [bpo-7633](https://bugs.python.org/issue?@action=redirect&bpo=7633).)

When [`Decimal`](https://docs.python.org/3.14/library/decimal.html#decimal.Decimal) instances are used with a string's [`format()`](https://docs.python.org/3.14/library/stdtypes.html#str.format) method, the alignment defaulted in the past to left-alignment. That default is now right-alignment, which fits numeric types more naturally. (Changed by Mark Dickinson; [bpo-6857](https://bugs.python.org/issue?@action=redirect&bpo=6857).)

Comparisons that involve a signaling NaN value (or `sNAN`) now raise [`InvalidOperation`](https://docs.python.org/3.14/library/decimal.html#decimal.InvalidOperation) instead of quietly returning true or false based on whichever comparison operator was used. The quiet variety of NaN values (or `NaN`) can now be hashed. (Fixed by Mark Dickinson; [bpo-7279](https://bugs.python.org/issue?@action=redirect&bpo=7279).)

- The [`difflib`](https://docs.python.org/3.14/library/difflib.html#module-difflib) module now generates output that works better with present-day **diff**/**patch** tools, thanks to one minor tweak: it uses a tab character rather than spaces to separate the filename in the header. (Fixed by Anatoly Techtonik; [bpo-7585](https://bugs.python.org/issue?@action=redirect&bpo=7585).)

- The Distutils `sdist` command now rebuilds the `MANIFEST` file every time, because even when neither the `MANIFEST.in` nor the `setup.py` file has changed, the user may have added new files that ought to be bundled in. (Fixed by Tarek Ziadé; [bpo-8688](https://bugs.python.org/issue?@action=redirect&bpo=8688).)

- The [`IGNORE_EXCEPTION_DETAIL`](https://docs.python.org/3.14/library/doctest.html#doctest.IGNORE_EXCEPTION_DETAIL) flag in the [`doctest`](https://docs.python.org/3.14/library/doctest.html#module-doctest) module will now disregard the name of the module that holds the exception under test. (Patch by Lennart Regebro; [bpo-7490](https://bugs.python.org/issue?@action=redirect&bpo=7490).)

- The [`Message`](https://docs.python.org/3.14/library/email.compat32-message.html#email.message.Message) class in the [`email`](https://docs.python.org/3.14/library/email.html#module-email) module will now take a Unicode-valued payload, converting it automatically to the encoding named by `output_charset`. (Added by R. David Murray; [bpo-1368247](https://bugs.python.org/issue?@action=redirect&bpo=1368247).)

- The [`Fraction`](https://docs.python.org/3.14/library/fractions.html#fractions.Fraction) class now takes, as constructor arguments, either a lone float or [`Decimal`](https://docs.python.org/3.14/library/decimal.html#decimal.Decimal) instance, or else two rational numbers. (Implemented by Mark Dickinson; rationals added in [bpo-5812](https://bugs.python.org/issue?@action=redirect&bpo=5812), and float/decimal in [bpo-8294](https://bugs.python.org/issue?@action=redirect&bpo=8294).)

Ordering comparisons (`<`, `<=`, `>`, `>=`) drawn between fractions and complex numbers now raise a [`TypeError`](https://docs.python.org/3.14/library/exceptions.html#TypeError). This corrects an oversight and brings the [`Fraction`](https://docs.python.org/3.14/library/fractions.html#fractions.Fraction) into line with the other numeric types.

- New class: the [`ftplib`](https://docs.python.org/3.14/library/ftplib.html#module-ftplib) module's [`FTP_TLS`](https://docs.python.org/3.14/library/ftplib.html#ftplib.FTP_TLS) delivers secure FTP connections by wrapping authentication—and the control and data transfers that follow—in TLS. (Contributed by Giampaolo Rodola; [bpo-2054](https://bugs.python.org/issue?@action=redirect&bpo=2054).)

The [`storbinary()`](https://docs.python.org/3.14/library/ftplib.html#ftplib.FTP.storbinary) method that handles binary uploads can now resume uploads by way of a newly added *rest* parameter (patch by Pablo Mouzo; [bpo-6845](https://bugs.python.org/issue?@action=redirect&bpo=6845).)

- New class decorator: the [`functools`](https://docs.python.org/3.14/library/functools.html#module-functools) module's [`total_ordering()`](https://docs.python.org/3.14/library/functools.html#functools.total_ordering) accepts a class that supplies an [`__eq__()`](https://docs.python.org/3.14/reference/datamodel.html#object.__eq__) method plus one of [`__lt__()`](https://docs.python.org/3.14/reference/datamodel.html#object.__lt__), [`__le__()`](https://docs.python.org/3.14/reference/datamodel.html#object.__le__), [`__gt__()`](https://docs.python.org/3.14/reference/datamodel.html#object.__gt__), or [`__ge__()`](https://docs.python.org/3.14/reference/datamodel.html#object.__ge__), and fills in the comparison methods that are absent. Because the `__cmp__()` method is on its way out in Python 3.x, this decorator simplifies defining ordered classes. (Added by Raymond Hettinger; [bpo-5479](https://bugs.python.org/issue?@action=redirect&bpo=5479).)

New function: [`cmp_to_key()`](https://docs.python.org/3.14/library/functools.html#functools.cmp_to_key) accepts an old-style comparison function—one taking two arguments—and returns a fresh callable suitable as the *key* parameter for functions like [`sorted()`](https://docs.python.org/3.14/library/functions.html#sorted), [`min()`](https://docs.python.org/3.14/library/functions.html#min) and [`max()`](https://docs.python.org/3.14/library/functions.html#max), and so on. Its main intended purpose is to assist in getting code to work with Python 3.x. (Added by Raymond Hettinger.)

- New function: the [`gc`](https://docs.python.org/3.14/library/gc.html#module-gc) module's [`is_tracked()`](https://docs.python.org/3.14/library/gc.html#gc.is_tracked) gives back true when the supplied instance is being tracked by the garbage collector, and false if not. (Contributed by Antoine Pitrou; [bpo-4688](https://bugs.python.org/issue?@action=redirect&bpo=4688).)

- The [`GzipFile`](https://docs.python.org/3.14/library/gzip.html#gzip.GzipFile) in the [`gzip`](https://docs.python.org/3.14/library/gzip.html#module-gzip) module now honors the context management protocol, which lets you write `with gzip.GzipFile(...) as f:` (contributed by Hagen Fürstenau; [bpo-3860](https://bugs.python.org/issue?@action=redirect&bpo=3860)), and it now realizes the [`io.BufferedIOBase`](https://docs.python.org/3.14/library/io.html#io.BufferedIOBase) ABC, letting you wrap it in [`io.BufferedReader`](https://docs.python.org/3.14/library/io.html#io.BufferedReader) for quicker processing (contributed by Nir Aides; [bpo-7471](https://bugs.python.org/issue?@action=redirect&bpo=7471)). You can also now override the modification time written into a gzipped file by handing an optional timestamp to the constructor. (Contributed by Jacques Frechet; [bpo-4272](https://bugs.python.org/issue?@action=redirect&bpo=4272).)

Gzip-format files may carry trailing zero bytes as padding; the [`gzip`](https://docs.python.org/3.14/library/gzip.html#module-gzip) module will now read past those trailing bytes. (Fixed by Tadek Pietraszek and Brian Curtin; [bpo-2846](https://bugs.python.org/issue?@action=redirect&bpo=2846).)

- New attribute: the [`hashlib`](https://docs.python.org/3.14/library/hashlib.html#module-hashlib) module now carries an `algorithms` attribute holding a tuple that names the supported algorithms. Within Python 2.7, `hashlib.algorithms` holds `('md5', 'sha1', 'sha224', 'sha256', 'sha384', 'sha512')`. (Contributed by Carl Chenet; [bpo-7418](https://bugs.python.org/issue?@action=redirect&bpo=7418).)

- The default [`HTTPResponse`](https://docs.python.org/3.14/library/http.client.html#http.client.HTTPResponse) class that the [`httplib`](https://docs.python.org/3.14/library/http.html#module-http) module relies on now does buffering, which makes reading HTTP responses considerably faster. (Contributed by Kristján Valur Jónsson; [bpo-4879](https://bugs.python.org/issue?@action=redirect&bpo=4879).)

The [`HTTPConnection`](https://docs.python.org/3.14/library/http.client.html#http.client.HTTPConnection) and [`HTTPSConnection`](https://docs.python.org/3.14/library/http.client.html#http.client.HTTPSConnection) classes now accept a *source_address* parameter, a `(host, port)` 2-tuple specifying the source address to be used for the connection. (Contributed by Eldon Ziegler; [bpo-3972](https://bugs.python.org/issue?@action=redirect&bpo=3972).)

- The `ihooks` module now handles relative imports. Keep in mind that `ihooks` is an older import-customization module that the `imputil` module, introduced in Python 2.0, has superseded. (Relative import support added by Neil Schemenauer.)

- The [`imaplib`](https://docs.python.org/3.14/library/imaplib.html#module-imaplib) module now handles IPv6 addresses. (Contributed by Derek Morr; [bpo-1655](https://bugs.python.org/issue?@action=redirect&bpo=1655).)
