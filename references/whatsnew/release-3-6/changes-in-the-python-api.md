# What's New In Python 3.6 / Changes in the Python API

### Changes in the Python API

- Combining the `'U'` mode flag together with `'+'` is no longer accepted by [`open()`](https://docs.python.org/3.14/library/functions.html#open). (Contributed by Jeff Balogh and John O'Connor in [bpo-2091](https://bugs.python.org/issue?@action=redirect&bpo=2091).)

- Ahead of DDL statements, [`sqlite3`](https://docs.python.org/3.14/library/sqlite3.html#module-sqlite3) has stopped quietly committing an open transaction.

- Under Linux, [`os.urandom()`](https://docs.python.org/3.14/library/os.html#os.urandom) will now wait until the system urandom entropy pool finishes initializing, strengthening security.

- Whenever [`importlib.abc.Loader.exec_module()`](https://docs.python.org/3.14/library/importlib.html#importlib.abc.Loader.exec_module) is provided, you must also provide [`importlib.abc.Loader.create_module()`](https://docs.python.org/3.14/library/importlib.html#importlib.abc.Loader.create_module).

- Should its **msg** argument go unset, [`PyErr_SetImportError()`](https://docs.python.org/3.14/c-api/exceptions.html#c.PyErr_SetImportError) now raises [`TypeError`](https://docs.python.org/3.14/library/exceptions.html#TypeError). Formerly the call merely returned `NULL`.

- On code objects, the [`co_lnotab`](https://docs.python.org/3.14/reference/datamodel.html#codeobject.co_lnotab) attribute changed its format so a negative line number delta is supported. Out of the box, Python does not emit bytecode carrying a negative line number delta. Code that leans on [`frame.f_lineno`](https://docs.python.org/3.14/reference/datamodel.html#frame.f_lineno), `PyFrame_GetLineNumber()` or `PyCode_Addr2Line()` stays unaffected. Code that decodes `co_lnotab` directly should switch to a signed 8-bit integer type for the line number delta, although that is needed solely to support apps relying on a negative line number delta. Consult `Objects/lnotab_notes.txt` for the `co_lnotab` format plus decoding guidance, and review the [**PEP 511**](https://peps.python.org/pep-0511/) for the reasoning.

- Functions inside the [`compileall`](https://docs.python.org/3.14/library/compileall.html#module-compileall) module now hand back booleans rather than `1` or `0` to signal success or failure. Since booleans subclass integers, this only matters where you ran identity checks against `1` or `0`. See [bpo-25768](https://bugs.python.org/issue?@action=redirect&bpo=25768).

- Fetching the `port` attribute from [`urllib.parse.urlsplit()`](https://docs.python.org/3.14/library/urllib.parse.html#urllib.parse.urlsplit) and [`urlparse()`](https://docs.python.org/3.14/library/urllib.parse.html#urllib.parse.urlparse) results now raises [`ValueError`](https://docs.python.org/3.14/library/exceptions.html#ValueError) when the value falls out of range, instead of handing back [`None`](https://docs.python.org/3.14/library/constants.html#None). See [bpo-20059](https://bugs.python.org/issue?@action=redirect&bpo=20059).

- Where it once raised [`PendingDeprecationWarning`](https://docs.python.org/3.14/library/exceptions.html#PendingDeprecationWarning), the `imp` module now raises a [`DeprecationWarning`](https://docs.python.org/3.14/library/exceptions.html#DeprecationWarning).

- To line up with their documented APIs, the modules listed next had absent APIs appended to their [`__all__`](https://docs.python.org/3.14/reference/simple_stmts.html#module.__all__) attributes: [`calendar`](https://docs.python.org/3.14/library/calendar.html#module-calendar), `cgi`, [`csv`](https://docs.python.org/3.14/library/csv.html#module-csv), [`ElementTree`](https://docs.python.org/3.14/library/xml.etree.elementtree.html#module-xml.etree.ElementTree), [`enum`](https://docs.python.org/3.14/library/enum.html#module-enum), [`fileinput`](https://docs.python.org/3.14/library/fileinput.html#module-fileinput), [`ftplib`](https://docs.python.org/3.14/library/ftplib.html#module-ftplib), [`logging`](https://docs.python.org/3.14/library/logging.html#module-logging), [`mailbox`](https://docs.python.org/3.14/library/mailbox.html#module-mailbox), [`mimetypes`](https://docs.python.org/3.14/library/mimetypes.html#module-mimetypes), [`optparse`](https://docs.python.org/3.14/library/optparse.html#module-optparse), [`plistlib`](https://docs.python.org/3.14/library/plistlib.html#module-plistlib), `smtpd`, [`subprocess`](https://docs.python.org/3.14/library/subprocess.html#module-subprocess), [`tarfile`](https://docs.python.org/3.14/library/tarfile.html#module-tarfile), [`threading`](https://docs.python.org/3.14/library/threading.html#module-threading) and [`wave`](https://docs.python.org/3.14/library/wave.html#module-wave). Consequently, fresh symbols get exported whenever `import *` runs. (Contributed by Joel Taddei and Jacek Kołodziej in [bpo-23883](https://bugs.python.org/issue?@action=redirect&bpo=23883).)

- During a relative import, [`ImportWarning`](https://docs.python.org/3.14/library/exceptions.html#ImportWarning) is raised whenever `__package__` fails to compare equal to `__spec__.parent`. (Contributed by Brett Cannon in [bpo-25791](https://bugs.python.org/issue?@action=redirect&bpo=25791).)

- If a relative import runs while no parent package is identifiable, [`ImportError`](https://docs.python.org/3.14/library/exceptions.html#ImportError) gets raised. Earlier, [`SystemError`](https://docs.python.org/3.14/library/exceptions.html#SystemError) might have been raised. (Contributed by Brett Cannon in [bpo-18018](https://bugs.python.org/issue?@action=redirect&bpo=18018).)

- Servers built atop the [`socketserver`](https://docs.python.org/3.14/library/socketserver.html#module-socketserver) module, those defined in [`http.server`](https://docs.python.org/3.14/library/http.server.html#module-http.server), [`xmlrpc.server`](https://docs.python.org/3.14/library/xmlrpc.server.html#module-xmlrpc.server) and [`wsgiref.simple_server`](https://docs.python.org/3.14/library/wsgiref.html#module-wsgiref.simple_server) among them, now restrict themselves to catching exceptions derived from [`Exception`](https://docs.python.org/3.14/library/exceptions.html#Exception). So whenever a request handler throws something like [`SystemExit`](https://docs.python.org/3.14/library/exceptions.html#SystemExit) or [`KeyboardInterrupt`](https://docs.python.org/3.14/library/exceptions.html#KeyboardInterrupt), [`handle_error()`](https://docs.python.org/3.14/library/socketserver.html#socketserver.BaseServer.handle_error) goes uncalled, and that exception halts a single-threaded server. (Contributed by Martin Panter in [bpo-23430](https://bugs.python.org/issue?@action=redirect&bpo=23430).)

- Should the user lack privileges, `spwd.getspnam()` now raises a [`PermissionError`](https://docs.python.org/3.14/library/exceptions.html#PermissionError) in place of [`KeyError`](https://docs.python.org/3.14/library/exceptions.html#KeyError).

- Whenever the underlying system call signals an error (for instance `EBADF`), the [`socket.socket.close()`](https://docs.python.org/3.14/library/socket.html#socket.socket.close) method now raises an exception. (Contributed by Martin Panter in [bpo-26685](https://bugs.python.org/issue?@action=redirect&bpo=26685).)

- For the `smtpd.SMTPChannel` and `smtpd.SMTPServer` constructors, the *decode_data* argument now defaults to `False`. As a result, whatever reaches `process_message()` is by default a bytes object, and `process_message()` receives keyword arguments. Code already revised to follow the deprecation warning that 3.5 produced stays unaffected.

- Every optional argument of the [`dump()`](https://docs.python.org/3.14/library/json.html#json.dump), [`dumps()`](https://docs.python.org/3.14/library/json.html#json.dumps), [`load()`](https://docs.python.org/3.14/library/json.html#json.load) and [`loads()`](https://docs.python.org/3.14/library/json.html#json.loads) functions, together with the [`JSONEncoder`](https://docs.python.org/3.14/library/json.html#json.JSONEncoder) and [`JSONDecoder`](https://docs.python.org/3.14/library/json.html#json.JSONDecoder) class constructors within the [`json`](https://docs.python.org/3.14/library/json.html#module-json) module, are now [keyword-only](https://docs.python.org/3.14/glossary.html#keyword-only-parameter). (Contributed by Serhiy Storchaka in [bpo-18726](https://bugs.python.org/issue?@action=redirect&bpo=18726).)

- A subclass of [`type`](https://docs.python.org/3.14/library/functions.html#type) that leaves `type.__new__` unoverridden can no longer rely on the single-argument form to obtain an object's type.

- Following [**PEP 487**](https://peps.python.org/pep-0487/), keyword arguments handed to [`type`](https://docs.python.org/3.14/library/functions.html#type) (apart from the metaclass hint, `metaclass`) are now uniformly forwarded to [`object.__init_subclass__()`](https://docs.python.org/3.14/reference/datamodel.html#object.__init_subclass__). So while [`type.__new__`](https://docs.python.org/3.14/reference/datamodel.html#object.__new__) and [`type.__init__`](https://docs.python.org/3.14/reference/datamodel.html#object.__init__) each now take arbitrary keyword arguments, `object.__init_subclass__()` (invoked from `type.__new__`) will by default refuse them. A custom metaclass that accepts extra keyword arguments will have to fix up its calls to `type.__new__` (whether made directly or by way of [`super`](https://docs.python.org/3.14/library/functions.html#super)) to match.

- Inside `distutils.command.sdist.sdist`, the `default_format` attribute is gone and no longer respected. The gzipped tarfile format now serves as the default everywhere, with no platform-specific choice applied. Where distributions get built on Windows and zip distributions are needed, set up the project using a `setup.cfg` file that holds the following:

```ini
[sdist]
formats=zip

```

Setuptools 26.0.0 also ported this behavior back to older Python versions.

- Across the [`urllib.request`](https://docs.python.org/3.14/library/urllib.request.html#module-urllib.request) module and the [`http.client.HTTPConnection.request()`](https://docs.python.org/3.14/library/http.client.html#http.client.HTTPConnection.request) method, when there is no Content-Length header field given and the request body is a file object, transmission now uses HTTP 1.1 chunked encoding. Where a file object must go to a HTTP 1.0 server, the caller now has to supply the Content-Length value. (Contributed by Demian Brecht and Rolf Krahl, with tweaks supplied by Martin Panter, in [bpo-12319](https://bugs.python.org/issue?@action=redirect&bpo=12319).)

- Rows produced by the [`DictReader`](https://docs.python.org/3.14/library/csv.html#csv.DictReader) are now of type [`OrderedDict`](https://docs.python.org/3.14/library/collections.html#collections.OrderedDict). (Contributed by Steve Holden in [bpo-27842](https://bugs.python.org/issue?@action=redirect&bpo=27842).)

- Where the platform offers no support for it, the `crypt.METHOD_CRYPT` will no longer get appended to `crypt.methods`. (Contributed by Victor Stinner in [bpo-25287](https://bugs.python.org/issue?@action=redirect&bpo=25287).)

- For [`namedtuple()`](https://docs.python.org/3.14/library/collections.html#collections.namedtuple), the *verbose* and *rename* arguments are now keyword-only. (Contributed by Raymond Hettinger in [bpo-25628](https://bugs.python.org/issue?@action=redirect&bpo=25628).)

- Under Linux, [`ctypes.util.find_library()`](https://docs.python.org/3.14/library/ctypes.html#ctypes.util.find_library) now consults `LD_LIBRARY_PATH` when hunting for shared libraries. (Contributed by Vinay Sajip in [bpo-9998](https://bugs.python.org/issue?@action=redirect&bpo=9998).)

- For better real-world compatibility, the [`imaplib.IMAP4`](https://docs.python.org/3.14/library/imaplib.html#imaplib.IMAP4) class now copes with flags that hold the `']'` character within messages the server sends. (Contributed by Lita Cho in [bpo-21815](https://bugs.python.org/issue?@action=redirect&bpo=21815).)

- Matching other write methods, the [`mmap.mmap.write()`](https://docs.python.org/3.14/library/mmap.html#mmap.mmap.write) function now hands back the count of bytes written. (Contributed by Jakub Stasiak in [bpo-26335](https://bugs.python.org/issue?@action=redirect&bpo=26335).)

- The [`pkgutil.iter_modules()`](https://docs.python.org/3.14/library/pkgutil.html#pkgutil.iter_modules) and [`pkgutil.walk_packages()`](https://docs.python.org/3.14/library/pkgutil.html#pkgutil.walk_packages) functions now hand back [`ModuleInfo`](https://docs.python.org/3.14/library/pkgutil.html#pkgutil.ModuleInfo) named tuples. (Contributed by Ramchandra Apte in [bpo-17211](https://bugs.python.org/issue?@action=redirect&bpo=17211).)

- Even where the pattern goes unmatched in the string, [`re.sub()`](https://docs.python.org/3.14/library/re.html#re.sub) now raises an error for invalid numerical group references inside replacement templates. The message for invalid group references now carries the group index plus the reference's position. (Contributed by SilentGhost, Serhiy Storchaka in [bpo-25953](https://bugs.python.org/issue?@action=redirect&bpo=25953).)

- For unrecognized compression values, [`zipfile.ZipFile`](https://docs.python.org/3.14/library/zipfile.html#zipfile.ZipFile) will now raise [`NotImplementedError`](https://docs.python.org/3.14/library/exceptions.html#NotImplementedError). Earlier a bare [`RuntimeError`](https://docs.python.org/3.14/library/exceptions.html#RuntimeError) came up. On top of that, invoking `ZipFile` methods against a closed ZipFile, or calling the [`write()`](https://docs.python.org/3.14/library/zipfile.html#zipfile.ZipFile.write) method on a ZipFile opened with mode `'r'`, will raise a [`ValueError`](https://docs.python.org/3.14/library/exceptions.html#ValueError). Formerly, a `RuntimeError` came up under those conditions.

- Where custom metaclasses meet zero-argument [`super()`](https://docs.python.org/3.14/library/functions.html#super) or direct method references to the implicit `__class__` closure variable, the implicit `__classcell__` namespace entry must now be forwarded up to `type.__new__` for initialisation. Neglecting that yields a [`DeprecationWarning`](https://docs.python.org/3.14/library/exceptions.html#DeprecationWarning) under Python 3.6 and a [`RuntimeError`](https://docs.python.org/3.14/library/exceptions.html#RuntimeError) under Python 3.8.

- Now that [`ModuleNotFoundError`](https://docs.python.org/3.14/library/exceptions.html#ModuleNotFoundError) exists, consumers of the import system may begin to expect import system replacements to throw that more pointed exception where fitting, instead of the broader [`ImportError`](https://docs.python.org/3.14/library/exceptions.html#ImportError). For forward compatibility with those consumers, authors of alternative import systems that wholly supersede [`__import__()`](https://docs.python.org/3.14/library/functions.html#import__) will need to revise their implementations so the new subclass gets raised whenever a module cannot be located at all. Authors of compliant plugins to the default import system should not have to change anything, since the default import system itself raises the new subclass where fitting.
