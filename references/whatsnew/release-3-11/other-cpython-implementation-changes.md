# What's New In Python 3.11 / Other CPython Implementation Changes — sys

When you convert between [`int`](https://docs.python.org/3.14/library/functions.html#int) and [`str`](https://docs.python.org/3.14/library/stdtypes.html#str) using radixes other than 2 (binary), 4, 8 (octal), 16 (hexadecimal), or 32 -- for instance base 10 (decimal) -- a [`ValueError`](https://docs.python.org/3.14/library/exceptions.html#ValueError) is now triggered whenever the string form carries more digits than a ceiling allows; this guards against possible denial of service exploits rooted in the algorithm's complexity. The behavior mitigates [**CVE 2020-10735**](https://www.cve.org/CVERecord?id=CVE-2020-10735). You may tune or switch off the ceiling through an environment variable, a command line flag, or [`sys`](https://docs.python.org/3.14/library/sys.html#module-sys) APIs. Consult the [integer string conversion length limitation](https://docs.python.org/3.14/library/stdtypes.html#int-max-str-digits) documentation. Out of the box the ceiling sits at 4300 digits when expressed as a string.

> [`sys.path`](https://docs.python.org/3.14/library/sys.html#sys.path) no longer admits bytes. That support quietly stopped working somewhere between Python 3.2 and 3.6, and nobody spotted it until after Python 3.10.0 had shipped. On top of that, restoring it would be awkward owing to how [`-b`](https://docs.python.org/3.14/using/cmdline.html#cmdoption-b) and [`sys.path_importer_cache`](https://docs.python.org/3.14/library/sys.html#sys.path_importer_cache) interact whenever [`str`](https://docs.python.org/3.14/library/stdtypes.html#str) and [`bytes`](https://docs.python.org/3.14/library/stdtypes.html#bytes) keys are mixed. (Contributed by Thomas Grainger in [gh-91181](https://github.com/python/cpython/issues/91181).)

### Other CPython Implementation Changes

- > The dunder methods [`__complex__()`](https://docs.python.org/3.14/reference/datamodel.html#object.__complex__) for [`complex`](https://docs.python.org/3.14/library/functions.html#complex) and [`__bytes__()`](https://docs.python.org/3.14/reference/datamodel.html#object.__bytes__) for [`bytes`](https://docs.python.org/3.14/library/stdtypes.html#bytes) are now provided so that the [`typing.SupportsComplex`](https://docs.python.org/3.14/library/typing.html#typing.SupportsComplex) and [`typing.SupportsBytes`](https://docs.python.org/3.14/library/typing.html#typing.SupportsBytes) protocols are honored. (Contributed by Mark Dickinson and Donghee Na in [bpo-24234](https://bugs.python.org/issue?@action=redirect&bpo=24234).)

- > A fresh internal hashing algorithm, `siphash13`, has been added. Its security characteristics mirror those of `siphash24`, yet it edges ahead on speed for lengthy inputs. [`str`](https://docs.python.org/3.14/library/stdtypes.html#str), [`bytes`](https://docs.python.org/3.14/library/stdtypes.html#bytes), and a few additional types now adopt it as the default backing [`hash()`](https://docs.python.org/3.14/library/functions.html#hash). [**PEP 552**](https://peps.python.org/pep-0552/) [hash-based .pyc files](https://docs.python.org/3.14/reference/import.html#pyc-invalidation) likewise switch to `siphash13`. (Contributed by Inada Naoki in [bpo-29410](https://bugs.python.org/issue?@action=redirect&bpo=29410).)

- > Whenever a live exception gets re-raised by a bare [`raise`](https://docs.python.org/3.14/reference/simple_stmts.html#raise) statement, the traceback bound to it is henceforth invariably `sys.exc_info()[1].__traceback__`. Consequently, any edits applied to the traceback inside the current [`except`](https://docs.python.org/3.14/reference/compound_stmts.html#except) clause carry through into the re-raised exception. (Contributed by Irit Katriel in [bpo-45711](https://bugs.python.org/issue?@action=redirect&bpo=45711).)

- > The way the interpreter state records handled exceptions (that is, `exc_info` or `_PyErr_StackItem`) now retains just the `exc_value` field; the `exc_type` and `exc_traceback` entries are gone, since both are recoverable from `exc_value`. (Contributed by Irit Katriel in [bpo-45711](https://bugs.python.org/issue?@action=redirect&bpo=45711).)

- > A new [command line option](https://docs.python.org/3.14/using/windows.html#install-quiet-option), `AppendPath`, was added for the Windows installer. Its behavior parallels `PrependPath`, except that it tacks the install and scripts directories onto the end rather than the front. (Contributed by Bastian Neuburger in [bpo-44934](https://bugs.python.org/issue?@action=redirect&bpo=44934).)

- > The [`PyConfig.module_search_paths_set`](https://docs.python.org/3.14/c-api/init_config.html#c.PyConfig.module_search_paths_set) field now has to carry `1` before initialization will draw on [`PyConfig.module_search_paths`](https://docs.python.org/3.14/c-api/init_config.html#c.PyConfig.module_search_paths) when building [`sys.path`](https://docs.python.org/3.14/library/sys.html#sys.path). Failing that, initialization rebuilds the path from scratch and discards whatever was placed into `module_search_paths`.

- > What the [`--help`](https://docs.python.org/3.14/using/cmdline.html#cmdoption-help) option prints now stays within 50 lines/80 columns. Details on [Python environment variables](https://docs.python.org/3.14/using/cmdline.html#using-on-envvars) together with [`-X`](https://docs.python.org/3.14/using/cmdline.html#cmdoption-X) options have moved behind the matching [`--help-env`](https://docs.python.org/3.14/using/cmdline.html#cmdoption-help-env) and [`--help-xoptions`](https://docs.python.org/3.14/using/cmdline.html#cmdoption-help-xoptions) flags, plus the brand-new [`--help-all`](https://docs.python.org/3.14/using/cmdline.html#cmdoption-help-all). (Contributed by ??ric Araujo in [bpo-46142](https://bugs.python.org/issue?@action=redirect&bpo=46142).)
