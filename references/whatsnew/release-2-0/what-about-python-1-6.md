# What’s New in Python 2.0 / What About Python 1.6?

### What About Python 1.6?

You can regard Python 1.6 as the Contractual Obligations Python release. Once the core team departed CNRI in May 2000, CNRI asked for a 1.6 release to be assembled that bundled all the Python work carried out at CNRI. Consequently Python 1.6 captures the condition of the CVS tree as it stood in May 2000, and its headline addition is Unicode support. Naturally, work didn’t stop in May, so a handful of corrections landed in the 1.6 tree to keep it forward-compatible with Python 2.0. For that reason 1.6 belongs to Python’s lineage rather than being a detour off to the side.

So is Python 1.6 worth much of your attention? Likely not. Both 1.6final and 2.0beta1 shipped on a single day (September 5, 2000), with the goal of wrapping up Python 2.0 roughly a month later. For anyone with applications to keep running, there’s scant benefit in disrupting things by switching to 1.6, repairing them, and then enduring a second wave of disruption a month afterward by switching to 2.0; heading directly to 2.0 is the smarter move. The genuinely compelling features documented here exist solely in 2.0, since a great deal of effort happened in the span from May to September.
