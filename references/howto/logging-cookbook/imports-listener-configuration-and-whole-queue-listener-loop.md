# Imports, listener configuration and whole queue listener loop

### Logging to a single file from multiple processes

The logging module is thread-safe, and writing to one file from several threads inside a single process *is* fine; however, directing *multiple processes* at one file *is not* supported, since Python offers no standard mechanism to serialize file access across separate processes. When several processes must funnel into a single file, one route is to have every process emit to a [`SocketHandler`](https://docs.python.org/3.14/library/logging.handlers.html#logging.handlers.SocketHandler) and run a dedicated process that hosts a socket server, reading the socket and writing the records to disk. (Should you prefer, a single thread within one of the already-running processes can take on that duty.) The discussion below walks through the technique with more depth and ships a functioning socket receiver you can treat as a base and tailor for your own programs.

Another option is to author a custom handler backed by the [`Lock`](https://docs.python.org/3.14/library/multiprocessing.html#multiprocessing.Lock) class out of the [`multiprocessing`](https://docs.python.org/3.14/library/multiprocessing.html#module-multiprocessing) module, using it to serialize how your processes reach the file. Note that the stdlib [`FileHandler`](https://docs.python.org/3.14/library/logging.handlers.html#logging.FileHandler) along with its subclasses does not rely on `multiprocessing`.

A further possibility is to route every logging event through a `Queue` paired with a [`QueueHandler`](https://docs.python.org/3.14/library/logging.handlers.html#logging.handlers.QueueHandler) toward a single process in your multi-process application.
