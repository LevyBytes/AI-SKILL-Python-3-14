# Python issue tracker and contributing fixes

### Using the Python issue tracker

When the issue concerns Python itself, send your report through the GitHub issues tracker ([https://github.com/python/cpython/issues](https://github.com/python/cpython/issues)). That GitHub issues tracker provides a web form into which you can type the relevant details and pass them along to the developers.

Before anything else, check whether someone has already reported the same problem. Beyond sparing the developers' time, this also tells you what has been done about it: perhaps a fix is already lined up for the upcoming release, or perhaps more detail is wanted (and you are welcome to supply it where you can!). Carry out that check by using the search box at the top of the page to search the tracker.

When the problem you want to raise is absent from the list, sign in to GitHub. Lacking a GitHub account, you can make one through the “Sign up” link. There is no way to file a bug report anonymously.

Once you are signed in, filing an issue becomes possible. Press the “New issue” button up in the top bar to open a fresh one.

Two fields make up the submission form: “Title” and “Comment”.

In the “Title” field, put a *very* brief summary of the problem; aiming for under ten words works well.

Within the “Comment” field, lay out the problem fully, covering both what you anticipated and what actually occurred. Make a point of noting any extension modules that played a role, plus the hardware and software platform in use (and version details wherever they matter).

Every issue report gets looked over by a developer, who decides what has to happen to put the problem right. Each time something is done on the issue, an update comes your way.

See also

[How to Report Bugs Effectively](https://www.chiark.greenend.org.uk/~sgtatham/bugs.html)

An article that explores at some length how to put together a helpful bug report, spelling out which kinds of information matter and the reasons they do.

[Bug Writing Guidelines](https://bugzilla.mozilla.org/page.cgi?id=bug-writing.html)

Guidance on composing a solid bug report. Parts of it are tied to the Mozilla project, yet much lays out good practice in general.

### Getting started contributing to Python yourself

Reporting the bugs you come across is one thing, but you are equally invited to send in patches that fix them. The [Python Developer’s Guide](https://devguide.python.org/) carries fuller details on how to begin patching Python. When questions come up, the [core-mentorship mailing list](https://mail.python.org/mailman3/lists/core-mentorship.python.org/) is a welcoming spot to get them answered, whatever they touch on in the work of resolving Python issues.
