# 3.3.7. Emulating container types

### 3.3.7. Emulating container types

You can define the methods below to build container objects. The [`object`](https://docs.python.org/3.14/library/functions.html#object) class provides none of them itself. Containers are typically [sequences](https://docs.python.org/3.14/glossary.html#term-sequence) (such as [`lists`](https://docs.python.org/3.14/library/stdtypes.html#list) or [`tuples`](https://docs.python.org/3.14/library/stdtypes.html#tuple)) or [mappings](https://docs.python.org/3.14/glossary.html#term-mapping) (like [dictionaries](https://docs.python.org/3.14/glossary.html#term-dictionary)), though they can stand for other kinds of containers too. The first group of methods serves to emulate either a sequence or a mapping; the distinction is that for a sequence the permitted keys should be the integers *k* satisfying `0 <= k < N` where *N* is the sequence's length, or else [`slice`](https://docs.python.org/3.14/library/functions.html#slice) objects, which delimit a range of items. Mappings are further encouraged to offer the methods `keys()`, `values()`, `items()`, `get()`, `clear()`, `setdefault()`, `pop()`, `popitem()`, `copy()`, and `update()`, behaving much like those on Python's standard [`dictionary`](https://docs.python.org/3.14/library/stdtypes.html#dict) objects. The [`collections.abc`](https://docs.python.org/3.14/library/collections.abc.html#module-collections.abc) module offers a [`MutableMapping`](https://docs.python.org/3.14/library/collections.abc.html#collections.abc.MutableMapping) [abstract base class](https://docs.python.org/3.14/glossary.html#term-abstract-base-class) that helps derive those methods from a starting set of `__getitem__()`, `__setitem__()`, `__delitem__()`, and `keys()`.

Mutable sequences ought to offer the methods [`append()`](https://docs.python.org/3.14/library/stdtypes.html#sequence.append), [`clear()`](https://docs.python.org/3.14/library/stdtypes.html#sequence.clear), [`count()`](https://docs.python.org/3.14/library/stdtypes.html#sequence.count), [`extend()`](https://docs.python.org/3.14/library/stdtypes.html#sequence.extend), [`index()`](https://docs.python.org/3.14/library/stdtypes.html#sequence.index), [`insert()`](https://docs.python.org/3.14/library/stdtypes.html#sequence.insert), [`pop()`](https://docs.python.org/3.14/library/stdtypes.html#sequence.pop), [`remove()`](https://docs.python.org/3.14/library/stdtypes.html#sequence.remove), and [`reverse()`](https://docs.python.org/3.14/library/stdtypes.html#sequence.reverse), just like Python's standard [`list`](https://docs.python.org/3.14/library/stdtypes.html#list) objects. Lastly, sequence types should support addition (that is, concatenation) and multiplication (that is, repetition) by defining the methods `__add__()`, `__radd__()`, `__iadd__()`, `__mul__()`, `__rmul__()` and `__imul__()` described farther down; they ought not define any other numerical operators.

Both mappings and sequences are encouraged to implement the `__contains__()` method so the `in` operator can be used efficiently; for a mapping, `in` should look through the mapping's keys, while for a sequence it should look through the values. Beyond that, both mappings and sequences are encouraged to implement the `__iter__()` method so the container can be iterated efficiently; for a mapping, `__iter__()` should walk the object's keys, while for a sequence it should walk the values.
