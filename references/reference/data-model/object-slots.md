# object.__slots__

object.__slots__

You may assign to this class variable a string, an iterable, or a sequence of strings that name the variables instances use. *__slots__* sets aside space for the declared variables and blocks the automatic creation of `__dict__` and *__weakref__* for each instance.

Notes on relying on *__slots__*:

- When inheriting from a class lacking *__slots__*, the `__dict__` and *__weakref__* attribute of the instances will always stay reachable.

- Lacking a `__dict__` variable, instances cannot be assigned fresh variables absent from the *__slots__* definition. Attempts to assign to an unlisted variable name raise [`AttributeError`](https://docs.python.org/3.14/library/exceptions.html#AttributeError). Should dynamic assignment of new variables be wanted, then append `'__dict__'` to the sequence of strings in the *__slots__* declaration.

- Lacking a *__weakref__* variable for each instance, classes defining *__slots__* offer no support for [`weak references`](https://docs.python.org/3.14/library/weakref.html#module-weakref) to its instances. Should weak reference support be needed, then append `'__weakref__'` to the sequence of strings in the *__slots__* declaration.

-

*__slots__* work at the class level: a descriptor is generated for every variable name listed. Because of this, you cannot rely on class attributes to supply default values for the instance variables that *__slots__* declares; if you did, that class attribute would clobber the descriptor that was just assigned.

- A *__slots__* declaration does not confine its effect to the single class that contains it. Slots declared in ancestors carry through to descendant classes. That said, instances of a descendant subclass acquire both a `__dict__` and *__weakref__* unless that subclass also supplies its own *__slots__* (which ought to list only the names of any *extra* slots).

- When a class declares a slot whose name also appears in a base class, the instance variable produced by the base class's slot becomes unreachable (apart from fetching its descriptor straight off the base class). Doing so leaves the program's meaning undefined. A check that forbids this may be introduced later.

- [`TypeError`](https://docs.python.org/3.14/library/exceptions.html#TypeError) is raised when nonempty *__slots__* are declared on a class that derives from a [`"variable-length" built-in type`](https://docs.python.org/3.14/c-api/typeobj.html#c.PyTypeObject.tp_itemsize) - for instance [`int`](https://docs.python.org/3.14/library/functions.html#int), [`bytes`](https://docs.python.org/3.14/library/stdtypes.html#bytes), and [`tuple`](https://docs.python.org/3.14/library/stdtypes.html#tuple).

- You may assign any non-string [iterable](https://docs.python.org/3.14/glossary.html#term-iterable) to *__slots__*.

- When a [`dictionary`](https://docs.python.org/3.14/library/stdtypes.html#dict) supplies the value of *__slots__*, its keys serve as the slot names. The dictionary's values let you attach a docstring to each attribute, which [`inspect.getdoc()`](https://docs.python.org/3.14/library/inspect.html#inspect.getdoc) picks up and which surfaces in the output produced by [`help()`](https://docs.python.org/3.14/library/functions.html#help).

- Assigning to `__class__` succeeds only when the two classes share identical *__slots__*.

- You can combine [Multiple inheritance](https://docs.python.org/3.14/tutorial/classes.html#tut-multiple) with several slotted parent classes, yet at most one parent may own attributes generated by slots (the remaining bases need empty slot layouts) - breaking this rule triggers [`TypeError`](https://docs.python.org/3.14/library/exceptions.html#TypeError).

- Should an [iterator](https://docs.python.org/3.14/glossary.html#term-iterator) supply *__slots__*, a [descriptor](https://docs.python.org/3.14/glossary.html#term-descriptor) is built for every value the iterator yields. The *__slots__* attribute, though, will end up as an empty iterator.
