# 6.2.10.3. Asynchronous generator functions

#### 6.2.10.3. Asynchronous generator functions

When a yield expression shows up inside a function or method declared with [`async def`](https://docs.python.org/3.14/reference/compound_stmts.html#async-def), that additionally marks the function as an [asynchronous generator](https://docs.python.org/3.14/glossary.html#term-asynchronous-generator) function.

Invoking an asynchronous generator function produces an asynchronous iterator referred to as an asynchronous generator object. From there, that object governs how the generator function runs. You ordinarily employ an asynchronous generator object within an [`async for`](https://docs.python.org/3.14/reference/compound_stmts.html#async-for) statement inside a coroutine function, much the way a generator object would serve inside a [`for`](https://docs.python.org/3.14/reference/compound_stmts.html#for) statement.

Each call to one of the asynchronous generator's methods produces an [awaitable](https://docs.python.org/3.14/glossary.html#term-awaitable) object, and execution kicks off the moment that object is awaited. From there, control advances to the very first yield expression, at which it pauses again, returning the `yield_list` value to the coroutine doing the awaiting. Just like an ordinary generator, pausing preserves the entire local state, which covers the present bindings of local variables, the instruction pointer, the internal evaluation stack, and whatever exception-handling state exists. Once execution resumes by awaiting the next object the asynchronous generator's methods return, the function carries on exactly as though the yield expression had merely been one more outside call. Which value the yield expression takes on after resuming hinges on the method that resumed it. Using `__anext__()` gives a result of [`None`](https://docs.python.org/3.14/library/constants.html#None). Otherwise, with `asend()`, the result becomes whatever value was handed to that method.

Should an asynchronous generator wind up exiting prematurely because of [`break`](https://docs.python.org/3.14/reference/simple_stmts.html#break), the cancellation of the caller task, or some other exception, the generator's async cleanup code executes and might raise exceptions or touch context variables within an unexpected context — possibly outside the lifetime of the tasks it relies on, or while the event loop is shutting down at the moment the async-generator garbage collection hook fires. Guarding against this requires the caller to deliberately shut down the async generator by invoking the `aclose()` method, which finalizes the generator and ultimately separates it from the event loop.

Inside an asynchronous generator function, yield expressions may appear at any spot within a [`try`](https://docs.python.org/3.14/reference/compound_stmts.html#try) construct. That said, when an asynchronous generator goes unresumed before being finalized (either by its reference count hitting zero or by garbage collection), a yield expression sitting inside a `try` construct might cause pending [`finally`](https://docs.python.org/3.14/reference/compound_stmts.html#finally) clauses to go unexecuted. Here, whichever event loop or scheduler is driving the asynchronous generator bears responsibility for invoking the asynchronous generator-iterator's `aclose()` method and running the coroutine object it returns, which in turn permits any outstanding `finally` clauses to run.

So that finalization is handled when the event loop ends, an event loop ought to supply a *finalizer* function that accepts an asynchronous generator-iterator and presumably invokes `aclose()` and runs the coroutine. Registering this *finalizer* is done by invoking [`sys.set_asyncgen_hooks()`](https://docs.python.org/3.14/library/sys.html#sys.set_asyncgen_hooks). The first time it is iterated, an asynchronous generator-iterator records the registered *finalizer* so it can be invoked at finalization time. To see a reference example of such a *finalizer* method, look at how `asyncio.Loop.shutdown_asyncgens` is implemented in [Lib/asyncio/base_events.py](https://github.com/python/cpython/tree/3.14/Lib/asyncio/base_events.py).

Writing the expression `yield from <expr>` produces a syntax error inside an asynchronous generator function.
